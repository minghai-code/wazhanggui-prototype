0. 族通用说明（本族其他页面不再重复）

0.1 这个族解决什么问题

把「一个人吃不下一整个阶梯」的采购凑成团：团长在商品详情选定目标档（阶梯价里的某一档）并按参团下限起下单，其他人以同一门槛参团；累计件数达到目标档才成团，全团按目标档单价结算，超档不升价；到期未达目标档则失效、全额退款。

不做会怎样：小买家凑不到起订量只能放弃，或线下自己找同行拼，平台拿不到这部分交易与履约数据。

0.5 状态机

依据 10b v2.1 §2.0.13：团 4 态；成团看累计是否达团长所选目标档，不看团长是否支付；商户/平台取消需运营审核。
对象状态进入条件出口 / 可执行
团进行中团长选目标档、支付首笔cum ≥ targetQty → 已成团；到期 cum < targetQty → 已失效；团长取消 / 商户申请（运营审核）/ 平台强制 → 已取消
团已成团cum ≥ targetQty按 targetPrice 锁档结算 → 各 GB 单转「待发货」→ 履约，终态；超档不升价
团已失效到期未达目标档（即便已过第一档也不算成团）全员原路全额退款（3 个工作日），终态
团已取消团长取消 / 商户申请 / 平台强制全员全额退款，终态、不可恢复
参团人待成团 → 已生成订单 / 已退款参团支付成功成团 → GB 单转待发货；失败或取消 → 已退款
  • 列表 Tab 归并：进行中 → 「进行中」；已成团 / 已失效 / 已取消 → 「已结束」（"已结束"是聚合词，不是单据状态）。不设「即将开始」Tab（恒空态，2026-11-11 删除）。
  • 参团人视角文案：进行中 →「待成团」；已成团 →「已生成订单」；已失效 →「拼单失败，已全额退款」；已取消 →「拼单已取消，款项已退回」。
