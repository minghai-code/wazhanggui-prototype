0.1 这族解决什么问题

第 18 届袜博会的移动端入口：看展会信息与日程、在线参观登记领入场码、现场扫码核销、按登记/核销状态解锁资料、展商在线自选展位并提交申请。

0.5 状态机

参观登记（6 态）

端上 key后台状态端上表现
pending待审核结果页「等待审核」+ 登记编号

资料访问策略：public 公开 / registered 需登记通过 / checkedin 需现场核销。

8.8 核销机制（跨端，2026-10-28 定稿）

问题结论
谁扫核销员角色的账号（同一账号体系），普通观众/展商看不到入口
用什么扫核销端内扫一扫（买家端 expo-checkin-scan.html，浏览器摄像头）；不依赖扫码枪、不依赖微信扫链接
码是什么证件号 + 签名串（端上只展示二维码图形）；不做成可外部打开的核销链接，避免任何人扫码即可操作
为什么不能外部扫链接扫码即打开核销页 = 把核销动作暴露给全网，靠登录墙挡不住「有登录态的人误点」
防伪后端校验签名 + 届次 + 有效期；无效码提示「非本届证件或签名失败」
幂等重复扫提示首次核销时间；后台记「扫码 / 手工补录」两种方式
兜底码破损/反光 → 手动输入证件号；断网 → 本地暂存待上传
权限落点复用统一用户体系与角色管理：新增角色「袜博会核销员」（含核销点 A/B 口绑定），不新建账号体系；同一账号可同时是买家/商户/核销员，登录后按角色多出入口
端上判定只认后台下发的角色标记；没有该角色 → 首页不显示入口、扫码页整页拦截
