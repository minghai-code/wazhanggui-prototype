F05 · 原料市场

依据等级：业务口径为 2026-11-03 业务确认（原料市场三条数据源 + 按品类区分市场）+ 后台分册 02-市场资源管理（场所「原料市场」）、04-商户管理（商户档案 / 品类字典）、10-商城运营（店铺）。凡后台缺依据的都标了「缺口 → 运营端待办」，不当已定规则用。 范围：原料市场首页、市场介绍、原料商户、筛选结果、商铺详情 5 页；打样 / 仓储 / 大宗集采入口本期下架（招标书未包含），对应页面暂留不进入口。

0.1 定位

袜子厂买原料的地方：找料（纱线 / 化纤 / 染料助剂 / 辅料橡筋 / 包装 / 纺配）→ 看商户与商铺 → 看店铺在售商品 → 进商品详情下单。

与「袜子市场」是同一套后台、不同品类：后台模块（场所、商户档案、店铺、商品）全部共用，靠主营品类把两类市场分开，不另建一套原料专用后台。

0.2 三条数据源（核心口径，2026-11-03 定）

区块数据源判定条件后台落点
原料品牌馆店铺（外采店铺属性）店铺类型 = 品牌店铺 且 店铺主档 主营品类 含原料大类外采店铺属性（categories[]）+ 我方店铺管理（类型/资质）
原料商户后台实体商户管理（04 商户档案）商户主营品类含原料大类，且商户状态 = 正常经营（可对外展示）04-商户管理 商户档案；档口/店面信息取 02 资源单元
原料商品店铺在售商品该店铺属原料市场（店铺主营品类含原料大类）→ 取该店铺在售商品外采商品库（按店铺 ID 反查）

三条都靠同一个开关：店铺/商户的「主营品类」是否命中原料大类。所以品类字典是这套区分机制的唯一支点（见 §0.5 缺口）。

✅ 2026-11-03 决策（业务已定）：「主营品类」要成为店铺的必备属性，外采店铺表也要加这个字段。 | 数据源 | 现状 | 决策 | |---|---|---| | 04 实体商户档案 | 已有主营品类 | 不动 | | 买家端「申请线上开店」 | 已收店铺主营品类（merchant-open-shop.html，字典多选、必选 ≥1） | 保留，作为店铺品类的写入来源 | | 外采店铺属性 | 没有主营品类，只有商品有分类 | 新增 categories[] 字段（改造项，见 §0.10） | 原因：袜子市场与原料市场都要同时展示线下店铺与线上商品，必须有一个字段能区分"卖袜子还是卖原料"。店铺没有这个字段，两个市场就分不开。 商品不加业务品类字段：原料商品 = 原料店铺的在售商品（按店铺反查）；外采自带的商品分类只用于超范围校验。

0.3 市场区分机制

后台一套数据
   ├─ 02 场所：大唐袜业城 / 原料市场 / 行政服务中心   ← 物理位置
   ├─ 04 商户档案：categories[] 主营品类（引用品类字典）
   ├─ 10 店铺：店铺类型（普通/品牌/自营）+ 所属商户
   └─ 外采商品库：商品（挂在店铺下）
        ↓ 按「主营品类是否属原料大类」分流
买家端：袜子市场（market-socks / market-map） ｜ 原料市场（market-material 系列）
规则内容
F05-R1原料大类集合 = 品类字典「原料纱线」大类下的全部品类项（含定案后补入的纱线/化纤长丝/染料助剂/辅料橡筋/包装物料/纺机配件 6 项，Y-11）；集合由运营端字典决定，端上不写死
F05-R2市场归属按品类大类推导，可多归属：主营品类含原料大类 → 进原料市场；含袜品大类 → 进袜子市场；混营（两类都有）→ 两边都展示（2026-11-03 业务确认）；品类为空 → 两边都不展示（运营端可筛「未归类」）
F05-R3商户状态非「正常经营」（暂停/冻结/清退）→ 不出现在原料商户与商品列表
F05-R4店铺未开线上店（仅线下）→ 出现在「原料商户」，但没有商品，商铺详情只展示资料与联系
F05-R5品牌馆仅收「品牌店铺 + 品牌资质通过」的原料店铺（与 F03 品牌馆同规则，只多一层品类过滤）

0.10 落地要求（2026-11-03 业务已定）

0.10.1 决策一句话

「主营品类」升级为店铺的必备属性：04 商户档案已有、开店申请已在收，外采店铺表也要加这个字段。 袜子市场与原料市场都靠它分流，不许再出现"没有字段可区分"的情况。

0.10.2 字段规格（三处同名同义）

位置字段必填来源说明
04 商户档案categories[]是线下建档 / 资料变更审核已有，字典取值
买家端 开店申请categories[]是（≥1）商户勾选，字典下发已有（#43 已改字典渲染、不预选）
外采店铺属性categories[]是审批通过写入；此后变更走资料变更审核新增（Y-12）；外采为源码整合（商城运营模块下），后台原型由运营端补
  • 取值：一律引用品类字典（04 §8.5b），端上不写死
  • 写入时机：开店审核通过 → 申请单 categories[] 写入店铺记录；线下商户自动建档时由 04 档案带过来
  • 变更：只能走「资料变更审核」，店长不能自改（防止品类被拿来刷市场曝光）
  • 空值处理：店铺无品类 → 两个市场都不展示，运营端「未归类」可筛（Y-12 已含）
