# F13 · AI 服务助手

> **依据等级**：`【招标需求】` 2026-11-06 业务转述——“基于意图识别和分级路由，引导客户清晰完善地表达诉求，将平台服务自助推荐给来访人，让轻服务快速响应”；`【客户确认·2026-11-06】` 本期**不做语音、不做多轮记忆、不做实时人工**，客服号码先用占位。
>
> **范围**：买家端 1 页（`ai-assistant.html`）+ 1 个全局悬浮球（`shared/ai-fab.js`，白名单 6 页注入）。

---

## 0. 族通用说明

### 0.1 这族解决什么问题

用户不清楚“平台有哪些服务、该去哪个页面办”。助手把“用户的一句话”翻译成“一个可点的地方”：

- 明确诉求 → 直接给**功能入口卡**，点了就到
- 诉求含糊 → **追问 1–2 轮**补全条件，再给入口
- 非功能问题（政策/费用/流程）→ **知识卡**直接答，附相关入口
- 听不懂 → **兜底**，给最常用入口 + 人工电话

不做会怎样：招标书这条需求缺失；且用户只能靠自己翻菜单，轻服务（政策、资质、流程）无人承接。

### 0.2 入口矩阵

| # | 入口 | 所在页面 | 目标 | 备注 |
|---|---|---|---|---|
| E1 | 悬浮球「AI」 | 首页 / 视频看货 / 进货单 / 我的 / 商品详情 / 搜索（6 页） | `ai-assistant.html` | 由 `shared/ai-fab.js` 注入，删一行即消失 |
| E2 | 对话内入口卡「去这里」 | `ai-assistant.html` | 各功能页 | 由意图路由表配置 |
| E3 | 顶部「人工」 | `ai-assistant.html` | 客服电话 + 投诉入口 | 不做实时会话 |

### 0.3 端间落点

| 项 | 内容 |
|---|---|
| 数据来源 | 运营端「**助手意图与路由配置**」（意图/关键词/槽位/目标页 URL/知识答案/启用），见运营端待办 **Y-24**；本期端上内置默认表（同结构） |
| 目标页 | 全部为买家端**已存在**页面（市场/询价/订单/店铺/政策/研学等），路由表只允许指向真实页面 |
| 跨端影响 | 无写操作；不产生工单、不分派客服 |
| 不涉及 | 商户端（商户侧助手另议）、运营端对话监控 |

### 0.4 术语

| 术语 | 含义 |
|---|---|
| 意图 | 用户一句话背后的办事目标（找货 / 询价 / 查单 / 开店 / 政策 / 知产 / 研学） |
| 槽位 | 意图成立需要的条件（在哪找、什么品类、什么量） |
| 分级路由 | L1 直达 / L2 追问 / L3 知识 / L4 兜底 四级处理 |
| 入口卡 | 带图标、名称、一句话说明与「去这里」的功能卡片 |
| 知识卡 | 标题 + 2–4 句答案 + 相关入口 |

### 0.5 口径

| 项 | 口径 |
|---|---|
| 识别方式 | **规则匹配**（关键词打分，命中词越长权重越高，单字不触发），不接模型；换模型时只替换识别层，端上数据结构不变 |
| 分级 | L1 直接给入口卡；L2 追问 ≤2 轮；L3 知识卡；L4 兜底 |
| 兜底原则 | 每轮回复**至少一个可点落点**，不允许纯文字结束 |
| 路由表 | 意图 → 页面 URL 唯一映射；**只允许配已上线页面**，配错即视为配置故障 |
| 客服 | 电话 `0575-8888xxxx`（**占位，待替换**）、服务时间 周一至周六 9:00–18:00 |
| 会话 | 一次性会话，**无多轮上下文记忆**（用户换句即重新识别） |

### 0.6 本期不做

语音输入 · 多轮上下文记忆 · 图片/拍照识别 · 实时人工客服（转接、排队、坐席）· 个性化推荐 · 情绪识别 · 会话数据看板 · 模型训练与微调 · 助手回答的点赞/纠错收集。

### 0.7 通知与消息

无。不产生站内信、不生成工单。

## 1. AI 服务助手 `ai-assistant.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 用一句话把用户带到正确功能，或直接回答轻服务问题 |
| 使用角色 | 游客 / 买家（未登录也可用，涉及个人数据的功能页自行拦截） |
| 入口 | 悬浮球（E1） |
| 前置 | 无 |
| 后置 | 功能页（入口卡）/ 投诉页（人工卡） |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 数据来源 | 运营端助手意图与路由配置（Y-24）；本期端上默认表 |
| 依赖页面 | 7 类意图共 24 个目标页，全部为本端已有页面 |
| 一致性 | 路由目标页下线时，配置侧必须同步停用，否则入口卡会 404 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 返回、助手名「袜掌柜小助手」、副标题「按意图智能匹配平台服务」、右侧「人工」 |
| 消息区 | 用户气泡（右、品牌色）/ 助手气泡（左、白底）；助手消息可附带入口卡、知识卡、选项 chips |
| 底部输入 | 快捷问法横滑条 + 输入框 + 发送；下方一行说明“识别与路由由平台配置” |

**回复形态（5 种，对应 4 级路由）**

| 形态 | 级别 | 组成 |
|---|---|---|
| 欢迎态 | — | 欢迎语 + 2 行说明 + 4 个快捷问法 |
| 追问态 | L2 | 问题一句 + 2–3 个选项 chips（点完即出结果） |
| 入口卡态 | L1 / L2 结果 | 说明一句 + 1–3 张入口卡（图标、名称、一句话、去这里） |
| 知识卡态 | L3 | 标题 + 2–4 句答案 + 相关入口链接 |
| 兜底态 | L4 | 「这个问题我还没学会」+ 3 个最常用入口 + 指向人工 |

| # | 意图 | 级别 | 追问 | 目标页 |
|---|---|---|---|---|

### 1.5 字段规格

| 区域 | 字段 |
|---|---|
| 入口卡 | 图标（底色渐变）、名称、一句话说明、目标 URL |
| 知识卡 | 标题、答案正文（最多 4 句）、相关入口（1–2 个） |
| 追问 | 问题文案、选项文案（每个选项绑定一组目标页或下一问） |
| 快捷问法 | 4 条首屏引导 + 底部横滑快捷条 |

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 |
|---|---|---|---|
| 悬浮球 | 6 个白名单页 | 始终 | 打开对话页 |
| 快捷问法 / 快捷 chips | 始终 | 始终 | 等价于用户发送该句 |
| 输入框 + 发送 | 始终 | 有内容 | 上屏用户气泡 → 助手 380ms 后回复 |
| 追问选项 | 追问态 | 始终 | 上屏所选文案 → 直接给入口卡 |
| 入口卡「去这里」 | 命中意图 | 目标页存在 | 跳目标页（原页面内跳转，不新开窗口） |
| 知识卡内链接 | 有相关入口 | 同上 | 同上 |
| 顶部「人工」 | 始终 | 始终 | 输出人工卡（电话 + 时间 + 投诉入口） |

### 1.7 业务规则与口径

| 编号 | 规则 | 触发 | 处理 |
|---|---|---|---|
| R-01 | 规则匹配，不接模型 | 每次发送 | 关键词打分（长度加权），得分 ≥2 才命中；功能意图优先于知识问答 |
| R-02 | 分级路由 | 命中后 | 有槽位需求 → L2 追问；无 → L1 直接给卡；知识类 → L3；未命中 → L4 |
| R-03 | 追问上限 2 轮 | L2 | 超过即给“最可能入口 + 兜底”，不让用户被反复追问 |
| R-04 | 每个回复必须有落点 | 所有回复 | 至少 1 个可点卡片或链接，禁止纯文字死胡同 |
| R-05 | 路由只指向真实页面 | 配置 | 目标页必须已上线；下线页面须同步停用，否则算配置故障 |
| R-06 | 无上下文记忆 | 每一次发送 | 只按当前这句话识别，不拼接历史 |
| R-07 | 不收集个人数据 | — | 不读订单、不读位置、不写工单；仅做导航 |
| R-08 | 客服号码占位 | 人工 | 显示 `0575-8888xxxx` 与工作时间，待业务给真实号码替换 |

### 1.8 异常与边界

| 场景 | 处理 | 提示文案 |
|---|---|---|
| 空输入 | 拦下不发 | 「说点什么吧」 |
| 识别不到 | 兜底态 | 「这个问题我还没学会」+ 3 个常用入口 |
| 只说单字（如“袜”） | 不触发意图（长度不足） | 走兜底 |
| 目标页下线 | 入口卡 404（配置故障，后台应停用该路由，见 Y-24） | — |
| 网络/脚本异常 | 欢迎语仍在，不白屏 | — |
