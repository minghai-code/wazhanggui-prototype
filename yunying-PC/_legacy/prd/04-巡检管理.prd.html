1. 页面定位

按计划派发巡检任务、记录执行情况，把"现场治理"变成有频次、有打卡、有点位、有问题数的可量化动作。

  • 使用者：物业主管（配计划 / 配点位 / 配检查项）、巡检员（移动端执行）
  • 下游：检查项判「异常」→ 一键生成问题单（WT），进 P6 问题上报按责任方分流
  • 本页职责边界（v1.1 修正）：PC 侧只配置 + 只读监控，不代巡检员判定点位结果。点位结果由巡检员在移动端 wuye-inspect.html 产生，回写本页任务详情与进度。
v1.1 变更（2026-10-30 · 第 3 次沟通 · 巡检点位与检查项必做） 原 v1.0 定位为"轻量版：只配区域，不配点位与检查项"，该口径已作废。 客户 2026-10-30 确认"点位与检查项必须做"，分册升至 v1.4 §8.5。本版据此把页面由 2 个 Tab 扩为 4 个 Tab，并补任务-点位联动、必检拦截、异常转问题单。

3. 巡检计划（Tab①）

字段必填说明
计划名称是如「A 栋日常巡检」
巡检区域是楼栋 + 楼层，可多选，至少 1 个
频次是每日 1 次 / 每周 2 次 / 每周 1 次 / 每月 1 次
巡检开始 / 结束时间是两个时间控件（time），不再手输字符串；结束必须晚于开始
巡检员是可多人轮值；候选来自「07 物业人员」中在岗且岗位含巡检员的人，搜索姓名/工号 + 多选，休假/停用的人不出现
巡检点位是先选区域 → 勾选该区域内的启用点位（按点位类型分组，点类型名可整类勾选）；任务只展开这里勾选的点位
状态是启用 / 停用
区域字典来源：巡检区域来自「02 市场资源管理 · 楼栋楼层维护」（resource-unit.html），本页只读引用，不在巡检模块新增区域。区域选择按楼栋分组，支持「整栋」一键勾选。

计划规则

编号规则
P-01启用计划每日凌晨自动生成当天任务；停用后不再生成，已生成任务不受影响
P-02停用当日已生成任务的计划需二次确认，提示「已生成 N 条任务不受影响」
P-03立即生成任务 = 手工补建，为每个区域各生成 1 条任务
P-04任务点位清单 = 计划勾选的点位 ∩ 该点位仍为启用状态
P-05某区域在勾选范围内无点位（或点位全被停用）→ 仍生成任务，但任务标「无点位」并提示主管去 Tab③ 补点位
为什么计划勾点位、而不是再选一遍"点位类型"：点位类型只决定"这个点要查哪些检查项"，是配置期的概念（Tab③④）；计划是执行期的概念，只需回答"这一趟要跑哪几个点"。若让计划再选类型，就出现"选类型→间接决定点位"的反向推导，用户看不懂（2026-10-30 反馈）。
【推导】检查项模板字段：分册 §8.5 只写"计划绑定检查项模板"，未定字段形态。本页按"多选点位类型"落（推荐方案），理由：检查项本身已按类型绑定，计划只需圈定范围，避免逐条勾选。若客户要求"逐条勾选检查项"，改为二级多选即可，任务展开逻辑不变。

4. 巡检点位（Tab③）

字段必填说明
点位编号是全局唯一，如 A3-04（列表展示 + 移动端定位标识）
点位名称是如「A 栋 3F 东侧消防通道」
所属区域是楼栋 + 楼层（与计划区域同字典）
点位类型是消防通道 / 灭火器 / 配电箱 / 公共卫生间 / 通道堆物 / 其他；决定自动带出哪些检查项
二维码值是现场贴码内容，全局唯一；移动端扫码定位到该点
状态是启用 / 停用（停用不影响历史记录）

点位规则

编号规则
PT-01二维码值全局唯一，重复即阻断（移动端扫错点位的根因）
PT-02点位编号全局唯一
PT-03停用点位不进入新生成任务的点位清单；已生成任务的点位记录保留
PT-04点位类型变更后，任务展开时按新类型带出检查项；已生成任务的检查项快照不回改
PT-05删除不做（只能停用），保证历史巡检记录可追溯

5. 检查项模板（Tab④）

字段必填说明
点位类型是检查项按类型绑定，不对单个点位配置
检查项名称是同类型下不可重名
顺序是移动端展示次序，同类型内从 1 开始
判定方式是正常 / 异常（固定两值）——异常时必须填照片 ≥1 + 说明
必检是必检项未判定 → 该点位不能提交；选检项只记录不拦截
状态是启用 / 停用（停用的检查项不再带出）

检查项规则

编号规则
IT-01判定方式只有「正常 / 异常」，不引入是/否、日期核对、尺寸核对等枚举（v1.1 修正；原 v1.0 原型自造的 4 种判定方式已删除）
IT-02同类型下检查项不可重名
IT-03顺序重复不阻断，但展示按 (顺序, 创建序) 稳定排序
IT-04判「异常」的检查项 → 移动端可一键生成 WT 问题单（带入点位 / 照片 / 检查项名 / 责任方=待判定）
IT-05停用检查项不影响历史点位记录中的判定结果

7. 任务与点位的联动（XJD 点位记录）

记录结构：XJD = 任务号 + 点位编号，每条记录 3 态。

stateDiagram-v2
    [*] --> 待检: 任务生成时展开点位清单
    待检 --> 正常: 检查项全部正常（或选检未判）
    待检 --> 异常: 任一检查项判异常 / 标记无法进入
    正常 --> [*]
    异常 --> [*]: 可生成 WT，记录保留并回填 WT 号
概念定义
应检点位数任务点位清单长度（计划区域 ∩ 启用点位 ∩ 模板类型）
已检点位数XJD.state ≠ 待检 的点位数，即「3/8」的分子
异常点位数XJD.state = 异常 的点位数
完成条件全部必检点位 ≠ 待检（选检点位待检不阻断）

任务详情抽屉结构

  1. 任务信息：所属计划 / 区域 / 巡检员 / 计划时间 / 打卡时间 / 发现问题数 / 巡检总结
  2. 点位置信（v1.1 新增）：三计数条（已检 / 待检 / 异常）+ 点位分组列表
  3. 每组一行：点位编号 · 名称 · 类型 · 已检项/总项 · 状态标签
  4. 异常点位行：显示「已转 WT-xxx」或「未转问题单」
  5. 无法进入点位：状态标「异常 · 无法进入」，并显示原因
  6. 执行留痕：时间轴（生成 / 打卡 / 上报 / 完成，标注来源「移动端 · 执行人 · 定位」）
