1. 定制订单 mall-order-custom.html

1.1 页面说明

项内容
页面目标查看定制大货订单：来源需求、是否经打样、打样费抵扣了多少、交期承诺
使用角色商城运营专员、商城运营主管
入口菜单 → 商城运营 → 订单管理 → 定制订单
前置需求选标（直接大货）或打样单样衣确认（先样品后大货）
后置履约由外采承载

1.2 本页端间关系

项内容
本页数据来源选标 / 样衣确认后生成
本页操作的跨端影响金额区展示「打样费抵扣 -¥N」，买家端订单同步
依赖的其他端页面mai-APP/custom-design.html、bulk-custom.html
不涉及的端商户端（履约走普通订单）
一致性要求抵扣额度与 P3 打样单强一致（同一条额度不能两处使用）

1.3 页面结构

区块内容
顶部标题 + 模拟创建定制单（演示前置校验）+ 导出
状态 Tab全部 / 待付款 / 待生产 / 生产中 / 待发货 / 已完成
统计卡（5）定制单总数 / 待生产 / 生产中 / 待发货 / 已抵扣打样费合计
筛选区定制单号·需求号·打样单号 + 批量类型 + 抵扣情况
列表11 列
详情抽屉基础信息 / 定制块 / 金额明细（含抵扣行） / 关联打样单 / 履约 / 日志

1.4 列表、筛选与排序

项目规则
默认排序创建时间倒序
分页不分页
筛选组合条件之间 且
批量类型个性小批量 / 企业大批量
抵扣有抵扣 / 无抵扣
空结果「暂无匹配的定制订单」

1.7 业务规则与计算口径

编号规则触发处理影响端
R-17创建前置：SP 必须样衣确认创建未确认拦截—
R-18打样费订单立减创建金额 = 数量×单价 − 抵扣两端
R-19抵扣须单列明细行渲染「打样费抵扣（来源打样单 X）」买家端（F3）
R-20额度一次性抵扣用后 P3 该单转"已用"P3
R-21直接大货无抵扣无 SP明细显示「无」—
R-22抵扣不超订单金额计算上限 = 商品金额—

1.8 异常与边界

类型场景系统行为提示文案
数据直接大货无打样单与抵扣【已实现】本单为「直接大货」，无关联打样单与抵扣
数据SP 未确认拦截创建【已实现】打样单未确认样衣，不能创建定制单
数据额度已用拦截【已实现】该打样单的抵扣额度已使用，不能重复抵扣
数据有抵扣金额明细行【已实现】打样费抵扣（来源打样单 {订单号}）
