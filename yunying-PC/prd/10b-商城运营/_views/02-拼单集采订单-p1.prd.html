1. 拼单集采订单 mall-order-group.html

1.1 页面说明

项内容
页面目标查看拼单集采产生的订单，回溯"谁发起的、谁参团、按哪档结算"
使用角色商城运营专员（查看/异常标记）、商城运营主管（取消）
入口菜单 → 商城运营 → 订单管理 → 拼单集采订单
前置拼单成团后由系统生成（每参团人一笔）
后置履约（支付/物流/售后）由外采 igshop 承载
拼单只由买家发起（F1），本页没有"新建拼单"入口。

1.2 本页端间关系

项内容
本页数据来源买家端发起拼单 → 成团后系统生成本类订单
本页操作的跨端影响取消订单 → 触发退款（外采规则）→ 买家端订单状态变更
依赖的其他端页面mai-APP/group-buy.html、group-buy-join.html、group-records.html
不涉及的端商户端（卖家侧走普通订单履约）
一致性要求成团后订单数 = 参团人数；单价 = 所在档单价

1.3 页面结构

区块内容
顶部标题 + 导出
状态 Tab全部 / 待付款 / 待发货 / 已发货 / 已完成 / 已取消（对齐外采主状态）
统计卡（5）订单总数 / 进行中（待付款）/ 已成团待发货 / 已失效（退款中）/ 本月成交额
筛选区订单号·拼单号·商品 + 拼单发起人
列表11 列
详情抽屉基础信息 / 拼单溯源 + 参团人明细 / 履约信息 / 操作日志

1.4 列表、筛选与排序

项目规则
默认排序成团时间倒序
分页不分页
筛选组合条件之间 且

1.6 交互规则

取消订单非终态主管原因必填 → 已取消 → 退款缺原因 → ML-11

1.7 业务规则与计算口径

编号规则触发处理影响端
R-07成团为每个参团人生成一笔成团订单数 = 参团人数买家端
R-08单价 = 所在档单价成团跨档按该档结算—
R-09未成团不进本页失效活动失效 + 全额退款，不产生订单买家端
R-10主状态跟随外采履约本页只读—
R-11取消需主管 + 原因取消触发退款两端

1.8 异常与边界

类型场景系统行为提示文案
数据未成团无订单（活动失效）【已实现】未达起拼档 → 活动已失效并全额退款
数据部分参团人未付款订单各自独立—
操作取消未填原因拦截【已实现】取消原因必填（将触发退款流程）
数据无匹配订单空态「暂无匹配的拼单订单」
