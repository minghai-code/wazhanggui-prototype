1. 样品打样订单 mall-order-sample.html

1.1 页面说明

项内容
页面目标跟进打样全过程：轮次、样衣状态、打样费抵扣额度是否已用
使用角色商城运营专员、商城运营主管
入口菜单 → 商城运营 → 订单管理 → 样品打样订单
前置定制需求中"仅样品定制"或"先样品后大货"选标后生成
后置样衣确认后可生成定制单（先样品后大货）；仅样品则结案
本页是"打样费抵扣"的账本：额度是否可用、被哪张定制单用掉，都在这里看。

1.2 本页端间关系

项内容
本页数据来源需求选标后生成；买家在端上支付打样费
本页操作的跨端影响样衣确认 → 端上解锁"下单大货"（生成 CZ）
依赖的其他端页面mai-APP/custom-design.html（申请打样 ¥200）
不涉及的端商户端（卖家履约走普通订单）
一致性要求打样费抵扣只在同一需求链路内有效；额度用后不可重复

1.3 页面结构

区块内容
顶部标题 + 导出
状态 Tab全部 / 待付款 / 待制样 / 已寄样 / 已完成 / 已取消
统计卡（5）打样单总数 / 待制样 / 已寄样待确认 / 待付款 / 已抵扣
筛选区打样单号·需求号·商品 + 抵扣状态（可用/已用）
