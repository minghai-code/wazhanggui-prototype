## 1. 样品打样订单 `mall-order-sample.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 跟进打样全过程：轮次、样衣状态、**打样费抵扣额度是否已用** |
| 使用角色 | 商城运营专员、商城运营主管 |
| 入口 | 菜单 → 商城运营 → 订单管理 → 样品打样订单 |
| 前置 | 定制需求中"仅样品定制"或"先样品后大货"选标后生成 |
| 后置 | 样衣确认后可生成定制单（先样品后大货）；仅样品则结案 |

> **本页是"打样费抵扣"的账本**：额度是否可用、被哪张定制单用掉，都在这里看。

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 需求选标后生成；买家在端上支付打样费 |
| 本页操作的跨端影响 | 样衣确认 → 端上解锁"下单大货"（生成 CZ） |
| 依赖的其他端页面 | `mai-APP/custom-design.html`（申请打样 ¥200） |
| 不涉及的端 | 商户端（卖家履约走普通订单） |
| 一致性要求 | 打样费抵扣只在同一需求链路内有效；额度用后不可重复 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题 + 导出 |
| 状态 Tab（7） | 全部 / 待付款 / 待制样 / 已寄样 / **样衣确认** / **已完结** / 已取消 |
| **统计卡（5）** | 打样单总数 / 待制样 / 已寄样待确认 / 待付款 / 已抵扣（**全部由 `S` 派生，不手写**） |
| 筛选区 | 打样单号·需求号·商品 + **样品收费方式**（免费提供 / 收费不可抵 / 收费可抵大货款）+ 抵扣状态（可用/已用） |
| 列表 | **10 列**：打样单号 / 来源需求 / 设计方案 / **样品收费方式** / 打样轮次 / 样品费 / 可抵扣 / **打样状态** / 关联定制单 / 操作 |
| 详情抽屉 | 基础信息（含**样品费支付**行）/ **打样块（含轮次时间线 + 抵扣额度 + 免费条件 / 支付与抵扣说明）** / **关联定制单** / 履约 / 日志 |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 创建时间倒序 |
| 分页 | 不分页 |
| 筛选组合 | 条件之间 **且** |
| Tab 口径 | 按**打样主状态** `mainState` 筛：已取消 / 已完结取终态，其余取打样子态；「待付款」Tab 单独按订单态 `state==='待付款'` 筛 |
| 抵扣状态 | 可用 / 已用 |
| 空结果 | 「暂无匹配的打样单」 |
| 红标 | 改样轮次 >3 显示「超 3 轮」 |

### 1.5 字段规格

| 列 | 字段 | 说明 |
|---|---|---|
| 打样单号 | `no` | `SP` + 日期 + 序号 |
| 来源需求 | `demand` | 可跳需求 |
| 设计方案 | `design` | 副行显示商品名 |
| **样品收费方式** | `sampleFeeWay` + `freeCond` | 三选一（§2.0.5）：`免费提供`（副行显示免费条件）/ `收样品费·不可抵` / `收样品费·可抵大货款` |
| 打样轮次 | `round` | >3 红标 |
| 样品费 | `fee` | **由收费方式推导**：免费 → ¥0.00；不可抵 / 可抵 → 商户报价金额（¥200 个性 / ¥500 企业） |
| 可抵扣 | `deduct` + `deductState` | `deduct` 由收费方式推导（免费与不可抵 = ¥0.00；可抵 = 样品费）；`deductState` = 无 / 可用 / 已用 |
| **打样状态（主列）** | `mainState` | 打样专属状态：未开始 / 待制样 / 已寄样 / 样衣确认 / 已完结 / 已取消；`state==='待付款'` 时右侧追加「样品费待付」小标，**不占主列** |
| 关联定制单 | `cz` | 可跳 P4 |
| 操作 | — | 详情 |

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 详情 | 始终 | 始终 | 抽屉 | — |
| **跳来源需求** | 有需求号 | 始终 | **跳 `mall-custom-demand.html?kw={需求号}`**：需求页按需求号预筛并自动打开该需求详情 | 需求号查不到 → 需求页显示"未匹配到该需求号，已按关键字筛选" |
| **查看定制单** | 有 `cz` | 始终 | 跳 P4 并定位 | 额度已用但无单号 → 提示已被使用 |
| 导出 | 始终 | 专员/主管 | Excel | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-12 | 样衣确认才解锁定制单 | 确认 | 端上出现"下单大货" | 买家端 |
| R-13 | 改样超 3 轮提醒 | round>3 | 列表红标 + 详情提示，不强制 | — |
| R-14 | 抵扣额度一次性 | 用于 CZ | 状态转"已用"并记录被哪单使用 | P4 |
| R-15 | 仅样品定制确认后结案 | 确认 | 不生成 CZ | — |
| R-16 | 样品收费方式三选一（§2.0.5） | 商户报价时选定 | 免费提供（可填免费条件，免付、无额度）/ 收费不可抵（买家务必付、无额度）/ 收费可抵大货款（买家务必付、额度 = 样品费） | 买家端 / 商户端 |
| R-17 | 样品费与抵扣额不得写死 | 数据初始化 | 一律由 `sampleFeeWay` 推导（`fee` / `deduct`），明细见上表字段规格 | — |
| R-18 | 免费样品不设「待付款」 | `sampleFeeWay='免费提供'` | 跳过支付直接进入待制样；抽屉「样品费支付」显示「无需支付」 | 买家端 |
| R-19 | 抵扣额度同链路 | 生成 CZ | 只在同一需求链路内有效，跨需求不抵扣；仅生成定制单时一次性使用（页头导出与列表右侧均标注） | P4 |
| R-20 | 待付款不占主列 | `state='待付款'` | 打样状态显示「未开始」+「样品费待付」小标（§2.0.4②：不套用订单 4 态做主列） | — |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 数据 | 改样 4 轮 | 红标 + 提示运营介入 | 【已实现】该打样单已改样 {n} 轮，建议运营介入 |
| 数据 | 额度已用 | 详情显示被哪张 CZ 使用 | 【已实现】该打样单的抵扣额度已被定制单 {订单号} 使用 |
| 数据 | 待付款超 24h | 订单取消 | — |
| 数据 | 无匹配 | 空态 | 「暂无匹配的打样单」 |
