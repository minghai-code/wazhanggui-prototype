1. 视频看货管理 mall-video.html

1.1 页面说明

项内容
页面目标维护买家端「视频看货」Tab 的短视频：一条视频 = 一个店铺 + 最多 1 个在售商品，视频下方直接出商品卡可下单
使用角色平台运营（全量、审核、代发、精选、强制下架）；商户账号（只见/只改本店）
入口菜单 → 10 商城运营 → 商品管理 → 视频看货管理
前置① 店铺已建档（店铺列表）② 商品已上架（商品列表）③ 视频文件已上传并转码完成
后置审核通过 → 买家端 F01 §3 视频看货宫格 + 沉浸式播放流；驳回 → 商户端 App / 商户后台可见原因

1.2 本页端间关系

项内容
本页数据来源视频本体由商户端 App（shanghu-APP #49）或本页（平台代发）创建；商品/店铺/在售状态来自商城侧
本页操作的跨端影响通过/驳回/强制下架/精选 → 买家端视频可见性与排序；驳回原因 → 商户端展示
依赖的其他端页面买家端 mai-APP/video.html（F01 §3）；商户端 App 视频看货管理 shanghu-APP/shop-video.html（列表）+ shop-video-edit.html（发布/编辑），2026-11-04 已建（分册 S09）
不涉及的端商户端后台（同一页面，按账号过滤）；无 09 内容管理入口（视频不走内容管理）
一致性要求视频关联商品必须在售且属同店铺；商品下架 → 买家端商品卡置灰（F01 R-10）

1.6 交互规则

元素可点条件点击后
新增视频始终打开编辑抽屉（来源固定「平台代发」）
Tab / 筛选 / 重置始终过滤列表并回到全量渲染
预览始终打开竖屏播放流（按当前筛选顺序）
审核（待审核）状态=待审核审核抽屉：通过（→已上架）/ 驳回（原因必填 →已驳回）
设为/取消精选状态=已上架切换精选（待审核不可设，提示拦截）
强制下架状态=已上架→已下架，写原因与操作人
换品已上架且商品失效打开编辑抽屉的换品模式，选新商品后回待审核
重新上架状态=已下架校验店铺未关闭 + 商品在售，通过则 →已上架
删除仅草稿二次确认后物理删除（不可恢复）
关联商品选择归属店铺已选定弹层只列该店铺在售商品，单选
清空关联商品始终置为「纯内容」（平台代发可保存；商户上传提交时拦截）
更换封面始终选图（建议 9:16），不选则取首帧

1.7 业务规则与口径

编号规则
V-1视频品类 = 关联商品的品类，只读派生，不建视频品类字典；无商品时品类为「—」
V-2一条视频最多 1 个商品；商户上传必挂本店在售商品，平台代发可不挂（买家端走兜底卡）
V-3上传入口两端并存（本页 + 商户端 App #49），同一份数据；审核与精选只在运营端
VD-R1已上架视频被修改（含换品）→ 自动转「待审核」并从买家端撤下
VD-R2店铺关闭 → 其名下已上架视频系统自动下架（留原因、不删除）；店铺重开后需逐条复审上架；已关闭店铺不可新增/编辑其视频
VD-R3提交人/时间、审核人/时间、下架人/时间/原因均留痕，列表状态列与「操作记录」可查
VD-R4话题标签已下线（2026-11-04）：无搜索/筛选/排序/统计落点、系统无标签库 → 本页与买家端均不提供该字段（实现时不要再加标签输入与展示）
VD-R5上传后系统转码，转码完成方可提交审核（技术状态，不进业务状态机）
VD-R6草稿删除不可恢复（二次确认）；已上架只能下架不能删除
VD-R7商品价格/起批量以商品库实时值为准；商品删除 → 商品卡「商品已删除」，需换品
VD-R8精选仅「已上架」可勾；强制下架、转待审核时自动取消精选

状态机

草稿 ──提交──→ 待审核 ──通过──→ 已上架 ⇄ 强制/自下架 ──→ 已下架
                   └──驳回（原因必填）──→ 已驳回 ──改后重提──→ 待审核

1.8 异常与边界

场景处理提示文案
归属店铺已关闭新建/编辑拦截；已上架视频加载时自动下架该店铺已关闭，不能新增或编辑其视频
关联商品已下架进「待处理」；买家端商品卡置灰关联商品不在售，请重新选择
商品已删除关联商品列显示「商品已删除」商品已删除
已关闭店铺的视频重新上架拦截店铺已关闭，不能重新上架
关联商品失效时通过审核拦截关联商品已下架，请先让商户换品或驳回
商户上传不挂商品提交拦截商户上传的视频必须关联 1 个本店在售商品
驳回未填原因拦截驳回需填写审核意见
非草稿删除拦截仅草稿可删除；已上架请用「强制下架」
待审核视频设精选拦截仅「已上架」视频可设精选
切换归属店铺原关联商品清空归属店铺已变更，原关联商品已清空，请重新选择
无数据空态暂无数据
无关联商品（预览）兜底卡该视频未关联商品
