1. 拼单集采订单 mall-order-group.html

1.1 页面说明

项内容
页面目标查看拼单集采产生的订单，回溯"谁发起的、谁参团、按哪档结算"
使用角色商城运营专员（查看/异常标记）、商城运营主管（取消）
入口菜单 → 商城运营 → 订单管理 → 拼单集采订单
前置支付即生单：参团人付款即生成一笔订单（状态「待成团」）；成团后统一转「待发货」
后置履约（支付/物流/售后）由外采 igshop 承载；团维度问题转「拼单集采需求管理」
拼单只由买家发起（F1），本页没有"新建拼单"入口。 两页分界：本页 = 逐笔订单（每位参团人一条）；mall-group-manage.html = 团（一个团一行，进度/取消/退款重试）。两页用团号双向跳转。

1.2 本页端间关系

项内容
本页数据来源买家端发起/参团 → 付款即生成订单（待成团）→ 成团转待发货
本页操作的跨端影响取消订单 → 触发退款（外采规则）→ 买家端订单状态变更
依赖的其他端页面mai-APP/group-buy.html、group-buy-join.html、group-records.html
本页跳转的后台页面mall-group-manage.html（团详情：进度 / 参团人 / 退款记录 / 重试）
不涉及的端商户端（卖家侧走普通订单履约）
一致性要求成团后订单数 = 参团人数；单价 = 所在档单价；团号与团页一一对应

区块内容

1.6 交互规则

元素显示条件可点条件点击后禁止表现

1.7 业务规则与计算口径

编号规则触发处理影响端
R-07成团后订单数 = 参团人数（每人一笔）成团数量对齐买家端
R-08单价 = 所在档单价成团跨档按该档结算，成团时统一重算—
R-09支付即生单：未成团订单存在，但为「待成团」，不进入履约（v1.1 修订，取代"未成团不进本页"）参团人支付生成订单（待成团）；团失效/取消 → 统一转「已取消（已退款）」买家端
R-10主状态跟随外采履约本页只读（待成团为拼单特有态）—
R-11取消需主管 + 原因取消触发本单退款两端
R-12团号与「拼单集采需求管理」一一对应—任一方向跳转均按同一 T 编号筛选—

1.8 异常与边界

类型场景系统行为提示文案
数据团未成团（进行中）订单为「待成团」，暂不发货【已实现】已付款、已生成订单，所在团尚未达目标档，达档后统一转待发货
数据团失效 / 取消订单转「已取消（已退款）」，退款进度在团页【已实现】所在团未成团或已取消，款项原路退回（3 个工作日）
数据部分参团人未付款订单各自独立（未付款不生成订单）—
操作取消未填原因拦截【已实现】取消原因必填（将触发退款流程）
数据无匹配订单空态「暂无匹配的拼单订单」
