## 0. 改造边界（商城为外采 igshop 源码）

| 项 | 结论 |
|---|---|
| 外采原状 | 「添加商品」页有 基本信息 / 销售信息 / 物流及配送 / 商品详情 / 高级信息 五个 Tab；销售信息内每个规格只有一口价、库存、市场价、成本价、规格编码，**没有阶梯价、没有拼单开关** |
| 本页性质 | **二次开发**，页面骨架、字段、校验、业务流程一律照搬外采；本系统只在「销售信息」内做增量 |
| 不改的 | 商品分类 / 品牌 / 分组 / 属性模板 / 商品服务 / 售后 / 批量操作等外采既有结构 |
| 口径前提 | **阶梯价形态已定稿**：按档位设置「起始数量 / 结束数量 / 阶梯单价」，可增删档位，末档结束数量可留空表示「以上」；统一规格一份阶梯表，多规格**每个规格各自一份**独立阶梯表。该形态不再讨论改造 |

## 1. 商品新增 `mall-product-add.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 商户 / 运营在同一套表单内维护商品，并配置**拼单开关**与**阶梯价**，保存后进入审核链路 |
| 使用角色 | 商户（有电商模块权限者自助发布）、商城运营专员（监督、纠错、代发） |
| 入口 | 菜单 → 商城运营 → 商品管理 → 新增商品；或商品列表行内「编辑 / 详情」带 `?id=` 进入编辑态 |
| 前置 | 商户已通过入驻审核、已开通线上店铺；商品品类在品类字典内 |
| 后置 | 提交 → 机器初筛（敏感词 + 敏感图）→ 命中警示级转人工判定 → 通过后上架；审核期间买家端仍展示上一版 |
| 编辑态 | `?id=商品编号` 打开时标题变「编辑商品」，页头出现编辑态提示条；字段取值沿用演示数据（原型不落库，接口实现以后端为准） |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 数据来源 | 商品图文由本页提交；阶梯价与拼单开关同属商品销售信息 |
| 跨端影响 | 审核通过后买家端商品详情按阶梯价**按实际下单数量落档计价**；`是否支持拼单=支持` 时买家端多出「发起拼单」入口，不支持则只有「立即下单」 |
| 依赖的其他端页面 | 买家端商品详情 / 拼单发起（消费方）；商户端商品发布（同一套表单，商户视角）；运营端 `mall-product-audit.html`（审核）、`mall-ops.html`（列表与入口） |
| 一致性要求 | 阶梯档位字段、拼单开关取值在三端（后台 / 商户端 / 买家端）**同一口径**，买家端不得自建档位规则 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「新增商品 / 编辑商品」+ 模块标签 + 「返回商品管理」 |
| 五个 Tab | 基本信息 / 销售信息 / 物流及配送 / 商品详情 / 高级信息（照搬外采） |
| **销售信息 ①** | 「是否支持拼单」开关（支持 / 不支持） |
| **销售信息 ②（统一规格）** | 阶梯价设置表：起始数量（双）/ 结束数量（双）/ 阶梯单价（元/双）/ 操作；「+ 添加档位」；末档留空 = 以上 |
| **销售信息 ③（多规格）** | 规格维度维护 + 规格明细表，末列为「阶梯价」，每个规格组合一行一个「阶梯价」按钮，打开该规格独立的档位编辑弹层 |
| 附加服务 | 商品附加服务列表（照搬外采） |
| 底部 | 取消 / 保存并提交审核 |

### 1.4 字段与规则

| 字段 | 规则 |
|---|---|
| 是否支持拼单 | 必选，默认「支持」；关闭后买家端不出现拼单入口 |
| 起始数量（双） | 必填；同规格内按升序排列 |
| 结束数量（双） | 可空，空 = 以上（不封顶） |
| 阶梯单价（元/双） | 必填；同一规格内随档位递增而单价不升 |
| 档位数量 | 统一规格至少 1 档；多规格每个规格至少 1 档 |
| 提交校验 | 统一规格未设置阶梯价 → 拦「统一规格未设置阶梯价，请至少添加一档」；多规格有任一规格未设置 → 拦「还有 N 个规格未设置阶梯价，请补全」 |
| 审核联动 | 提交后不直接同步买家端，先机审再人审；拼单开关与阶梯价随商品一起过审 |

### 1.5 状态与留痕

| 环节 | 表现 |
|---|---|
| 保存提交 | 提示「已提交（支持/不支持拼单 · N 个规格阶梯价均已设置）：已进入机器初筛」 |
| 机审通过 | 进 `mall-product-audit.html` 人审队列（店铺开关决定是否需人审） |
| 人审通过 | 商品上架，买家端可见新版本；列表页状态变「已通过」 |
| 编辑已上架商品 | 重审期间**老版本继续展示**，通过后替换 |

### 1.6 验收要点

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-01 | 统一规格不添加任何档位直接提交 | 阻断并提示至少添加一档 |
| AC-02 | 多规格中某规格未设阶梯价直接提交 | 阻断并提示未设置规格数量 |
| AC-03 | 末档结束数量留空 | 显示为「以上」，保存无报错 |
| AC-04 | 关闭拼单开关提交 | 提示为「不支持拼单」；买家端无发起拼单入口 |
| AC-05 | 带 `?id=` 打开 | 标题变「编辑商品 + 编号」，页头出现编辑态提示条 |
| AC-06 | 提交后查看审核中心 | 待审队列出现该商品，机审结论与命中项可查 |

## 2. 商品列表 `mall-ops.html`

### 2.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 商品总台账：看状态、进审核、纠错编辑、查驳回原因 |
| 入口 | 菜单 → 商城运营 → 商品管理 → 商品列表 |
| 列表列 | 商品编号 / 商品 / 商户 / 品类 / 提交时间 / 机审结论 / 审核状态 / 操作 |
| 操作列 | **编辑**（进 `mall-product-add.html?id=`，维护阶梯价与拼单开关）· 详情（同编辑页只读回显）· 审核 / 复核 / 查看机审（进审核页并带单号）· 驳回原因（人工判定结论留痕）· 查看（商户修改中） |
| 状态枚举 | 待机审 / 机审拦截 / 待人审 / 已通过 / 已驳回 / 需修改（与 `mall-product-audit.html` 取值一致） |

### 2.2 审核结论回写

| 项 | 规则 |
|---|---|
| 回写方向 | 审核页人审「通过 / 驳回」、拦截单「复核放行 / 维持拦截」均回写同一份商品状态 |
| 列表表现 | 列表加载时合并回写结果：通过 → 已通过（机审结论置为通过），驳回 / 维持拦截 → 已驳回，复核放行 → 待人审 |
| 目的 | 让「审核通过后阶梯价与拼单开关才生效」有可见的状态流转，不再两页各一套 mock |

### 2.3 验收要点

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-07 | 商品列表点「编辑」 | 进商品页且标题为编辑态，页头有编辑提示条 |
| AC-08 | 审核页通过某商品后回到列表 | 该商品状态变「已通过」，机审结论列显示通过 |
| AC-09 | 审核页驳回后回到列表 | 该商品状态变「已驳回」，行内可查驳回原因 |
| AC-10 | 列表内任一操作 | 无 toast 假跳；跳转目标页均存在 |

## 3. 遗留与边界

| 项 | 说明 |
|---|---|
| 起批量字段 | 商品表单不新增独立「起批量」字段；参团下限与起批口径按 `10b §2.0.13` 由目标档 / 阶梯最小档解释，PRD 侧已收口 |

| 页 PRD 归属 | 本文件同时承载「商品新增」与「商品列表」两页说明，两页各有一条映射 |
