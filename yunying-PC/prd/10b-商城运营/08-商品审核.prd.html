10b-08 商品审核 · 运营端页面说明

端：运营端 PC　｜　模块：10 商城运营 → 商品管理　｜　页面：mall-product-audit.html（本次新增） 页面版本：v1.0（2026-11-09）　｜　依据：招标 2.1.3-97 商品自动审核（机器初筛 + 人工判定双重审核） 模块通用说明见同目录 01-个性定制需求管理.md §0。 关联改造：mall-ops.html（商品列表）、mall-product-add.html（新增商品）、mall-shop-setting.html（店铺设置 · 商品审核开关）

0. 改造边界（商城为外采 igshop 源码）

项结论
外采原状商品只有「待审核 / 已通过 / 已驳回 / 需修改」四态 + 「店铺商品审核」开关（开启=免审直接上架），没有敏感词/敏感图审核链路
本页性质新增改造页（二开），不属于外采菜单；商品字段、列表列、上下架、编辑流程仍以外采为准
新增数据表goods_audit（审核单）、goods_audit_hit（命中明细）、sensitive_word（敏感词库）、sensitive_image_rule（敏感图策略）——全部为新增表，不改外采商品主表结构（仅加可空的 audit_id / audit_state 冗余字段便于列表展示）
不改的商品表单字段、SKU/规格、库存、上下架按钮、分类品牌等一切外采用户可见结构
口径变更外采「店铺商品审核」开关语义收窄：不再决定是否过机审，只决定「机审通过后是否还需人工判定」；机审强制常开、不可关闭（否则无法满足招标的"确保上架商品合规"）

1. 商品审核 mall-product-audit.html

1.1 页面说明

项内容
页面目标让商品在上架前自动过一遍「敏感词 + 敏感图」机器初筛，命中风险的转人工判定，未通过不能出现在买家端
解决痛点商户自助上传商品量大、运营肉眼审不完；涉黄涉暴、违禁品、医疗宣称、绝对化用语、侵权等违规内容一旦上架即构成平台风险
使用角色商城运营专员（审核判定）、商城运营主管（规则与词库维护、复核放行）
入口菜单 → 商城运营 → 商品管理 → 商品审核；或商品列表行内「审核 / 复核」带单号进入（?aid=）
前置商品由商户提交 / 编辑重提 / 批量导入 / 平台代发
后置通过 → 商品在买家端展示；驳回 → 原因回传商户端，可修改重提；拦截 → 不上架并留档

1.2 本页端间关系

项内容
本页数据来源商品图文来自外采商品表（只读）；审核单、命中项、词库、策略为本系统新增
本页操作的跨端影响判定通过 → 买家端商品可检索/可访问；驳回 → 商户端收到驳回原因（原因枚举，不含评分细节）；拦截 → 买家端不可访问、商户端提示违规
依赖的其他端页面商户端商品发布/编辑页（提交入口）、买家端商品列表与详情（消费方）；运营端 mall-ops.html（列表状态与入口）
不涉及的端订单、物流、结算；视频看货审核（mall-video.html 已有独立审核链路，两套不合并）
一致性要求审核状态与商品上下架状态解耦：audit_state 决定"能否上架"，外采 goods_status 决定"上架后是否在售"；审核状态取值与 mall-ops.html、mall-shop-setting.html 三处必须一致

1.4 列表、筛选与排序

项目规则
默认分段待人审（运营最常处理的队列）
默认排序提交时间正序（先到先审，避免超时）；同时间按审核单号
筛选组合条件之间 且；「只看超时」与分段叠加生效
分页不分页（单页队列 < 50；二期数据量上来后按 20 条/页）
空结果「该状态下暂无商品」/「暂无拦截记录」/「没有匹配的敏感词」
超时标识待人审 > 24h：等待列红字加粗 + 状态列「已超 24h」+ 统计卡括号提示

1.6 关键规则

#规则
R-1机审不可跳过：新商品、批量导入、平台代发一律先过机审；机审开关不提供给运营关闭的入口
R-2拦截级直接不上架：命中拦截级敏感词、或敏感图置信度 ≥ 阈值且处置为「拦截」→ 状态 machine_blocked，不进人工队列，买家端搜不到、详情不可访问
R-3警示级 / 灰区转人工：命中警示级词、或图置信度处于阈值区间且处置为「转人工」→ pending_manual
R-4双重审核：机审全通过后，若店铺未开启「机审通过后免人工判定」→ 仍需人工判定；开启则直接 passed
R-5编辑已上架商品重新过审：审核期间买家端继续展示上一版；审核不通过时老版本保留，商品不消失
R-6人工判定只有两个出口：通过并上架 / 驳回（原因枚举 + 说明必填）；机审拦截时只有复核放行 / 维持拦截
R-7误报可标可沉淀：命中项可「判为误报」，风险分即时下调，全部误报则机审结论转 pass；误报记录用于二期词库调优（不自动加白名单）
R-8复核放行必须填理由：拦截商品放行后转入人工队列，拦截记录保留（不删除），操作写留痕
R-9合规留痕：审核单、命中项、判定人、判定时间、驳回原因全量留档，可按商品/商户追溯导出
R-10规则即时生效：词库、阈值、处置策略保存即生效，不设发布版本；每次变更进「规则变更留痕」
R-11SLA：人工判定 24h 内完成，超时红标提示（不做自动通过，避免合规风险）
R-12单字不生效：敏感词 < 2 字不允许保存，避免误伤（如「袜」）

1.7 状态机与枚举

提交 → pending_machine（机审中，秒级）
        ├─ 拦截级命中 → machine_blocked ──复核放行──→ pending_manual
        │                              └─维持拦截──→ rejected（原因：涉黄涉暴等）
        ├─ 警示/灰区   → pending_manual ─通过→ passed
        │                              └驳回→ rejected
        └─ 全部通过    → pending_manual（需人审）或 passed（免人审）
rejected → 商户修改重提 → pending_machine（version_no +1）
任意在途态 → 商品被删除 / 店铺被关闭 → invalid（审核单失效，退出队列、留档保留）
差异声明（D-29）：invalid 为分册 §3.7 PA-R10 的设计口径，当前原型未实现（队列无删除入口，演示不受影响），已记 harness/backlog.md。同一商品重复提交的幂等校验同样待开发实现。
枚举取值
驳回原因涉黄涉暴内容 / 侵权或假冒 / 违规宣传用语（医疗功效·绝对化） / 图片不合规 / 类目错放·商品信息不实 / 其他（备注必填）
命中等级拦截级（自动不上架）/ 警示级（转人工）
图识别类别涉黄涉暴（裸露·色情）/ 涉黄涉暴（武器·暴力）/ 违禁品 / 侵权 LOGO·水印 / 二维码·外部引流

1.8 验收

#操作预期
AC-01商户提交含「仿真枪」的商品机审 block，状态机审拦截、不上架；拦截记录可见，买家端搜不到
AC-02提交含「治脚气」的商品机审 warn 转人工；审核抽屉高亮命中词与位置，人工驳回后商户端收到原因
AC-03含软色情图片（置信度 0.72，阈值 0.70）机审判定命中并标红对应图片；运营可判误报并放行
AC-04机审全通过且店铺未开免人审商品停在待人审，运营通过后才上架
AC-05打开店铺「机审通过后免人工判定」机审通过即上架；命中拦截级内容仍不上架
AC-06编辑已上架商品并重提重新进机审，审核期间买家端仍展示上一版；驳回后老版本不消失
AC-07拦截商品点「复核放行」但不填理由拦截并提示必填，不放行
AC-08新增敏感词「大牌同款」为警示级立即生效；下次机审该类文案转人工，规则变更留痕有记录
AC-09图片阈值 0.70 → 0.80同一张 0.72 的图不再命中，原本待审商品机审结论变为通过
AC-10待审 > 24h 的商品等待列红字、状态列「已超 24h」、统计卡括号提示
AC-11从商品列表行内点「审核」带 ?aid= 进入审核中心并自动打开该商品审核抽屉
AC-12导出审核留痕含机审风险分、命中项、人工判定人/时间/原因
