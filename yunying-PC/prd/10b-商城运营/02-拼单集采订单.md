## 1. 拼单集采订单 `mall-order-group.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 查看拼单集采产生的订单，回溯"谁发起的、谁参团、按哪档结算" |
| 使用角色 | 商城运营专员（查看/异常标记）、商城运营主管（取消） |
| 入口 | 菜单 → 商城运营 → 订单管理 → 拼单集采订单 |
| 前置 | **支付即生单**：参团人付款即生成一笔订单（状态「待成团」）；成团后统一转「待发货」 |
| 后置 | 履约（支付/物流/售后）由外采 igshop 承载；团维度问题转「拼单集采需求管理」 |

> **拼单只由买家发起**（F1），本页**没有"新建拼单"入口**。
> **两页分界**：本页 = **逐笔订单**（每位参团人一条）；`mall-group-manage.html` = **团**（一个团一行，进度/取消/退款重试）。两页用`团号`双向跳转。

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 买家端发起/参团 → **付款即生成订单**（待成团）→ 成团转待发货 |
| 本页操作的跨端影响 | 取消订单 → 触发退款（外采规则）→ 买家端订单状态变更 |
| 依赖的其他端页面 | `mai-APP/group-buy.html`、`group-buy-join.html`、`group-records.html` |
| 本页跳转的后台页面 | `mall-group-manage.html`（团详情：进度 / 参团人 / 退款记录 / 重试） |
| 不涉及的端 | 商户端（卖家侧走普通订单履约） |
| 一致性要求 | 成团后订单数 = 参团人数；单价 = 所在档单价；团号与团页一一对应 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题 + 导出 + **去团管理** + 从团页跳入时的来源提示条 |
| 状态 Tab | 全部 / **待成团** / 待发货 / 已发货 / 已完成 / 已取消（待成团为本场景特有中间态，其余对齐外采主状态） |
| **统计卡（5）** | 订单总数 / 待成团 / 已成团履约中（待发货+已发货）/ 已完成 / 已取消（已退款） |
| 筛选区 | 订单号·拼单号·商品 + 拼单发起人 |
| 列表 | **11 列** |
| 详情抽屉 | 基础信息 / **拼单溯源 + 参团人明细（标「本单」）** / **本单状态说明** / 履约信息 / 操作日志 |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 成团时间倒序 |
| 分页 | 不分页 |
| 筛选组合 | 条件之间 **且** |
| 状态 Tab | 与列表状态互斥联动 |
| 空结果 | 「暂无匹配的拼单订单」 |

### 1.5 字段规格

| 列 | 字段 | 说明 |
|---|---|---|
| 订单号 | `no` | `GB` + 日期 + 序号 |
| 拼单号 | `gid` | **`T` + 年月日 + 3 位流水（团号），点击跳「拼单集采需求管理」团详情** |
| 发起人 | `starter` | 脱敏（团长） |
| 参团人 | `members` | 人数，详情看明细 |
| 商品 | `goods` | 副行显示档位达成情况 |
| 数量 | `qty` | **本单**数量（非团累计） |
| 单价（目标档） | `price` | 按**目标档单价**结算；预付价 = 结算价，**超档不升价** |
| 金额 | `amount` | 本单金额 = 数量 × 目标档单价 |
| 成团时间 | `doneAt` | 未成团为 — |
| 订单状态 | `state` | 待成团 / 待发货 / 已发货 / 已完成 / 已取消 |
| 操作 | — | 详情 |

**参团人明细（详情内）**：参团人 · 数量 · 实付 · **占团比**（= 个人数量 ÷ 本团累计数量）；当前订单对应行标「本单」+ 合计行。

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 详情 | 始终 | 始终 | 抽屉 | — |
| **拼单号 / 跳团** | 有团号 | 始终 | **跳 `mall-group-manage.html?tid={团号}`**（团维度看进度与退款） | — |
| **去团管理** | 始终 | 始终 | 跳团列表 | — |
| 异常标记 | 始终 | 专员/主管 | 填备注 → 入异常清单 | 缺备注 → 拦截 |
| **取消订单** | 非终态（待成团/待发货/已发货） | **主管** | 原因必填 → 本单已取消 → 退款 | 缺原因 → ML-11 |
| 导出 | 始终 | 专员/主管 | Excel | — |

> **取消单笔 vs 取消全团**：本页取消**只影响本单**，不改团状态；要整团退款请走「拼单集采需求管理」的强制取消（仅进行中）。

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-07 | 成团后订单数 = 参团人数（每人一笔） | 成团 | 数量对齐 | 买家端 |
| R-08 | 单价 = 所在档单价 | 成团 | 跨档按该档结算，成团时统一重算 | — |
| R-09 | **支付即生单：未成团订单存在，但为「待成团」，不进入履约**（v1.1 修订，取代"未成团不进本页"） | 参团人支付 | 生成订单（待成团）；团失效/取消 → 统一转「已取消（已退款）」 | 买家端 |
| R-10 | 主状态跟随外采 | 履约 | 本页只读（待成团为拼单特有态） | — |
| R-11 | 取消需主管 + 原因 | 取消 | 触发本单退款 | 两端 |
| R-12 | 团号与「拼单集采需求管理」一一对应 | — | 任一方向跳转均按同一 `T` 编号筛选 | — |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 数据 | 团未成团（进行中） | 订单为「待成团」，暂不发货 | 【已实现】已付款、已生成订单，所在团尚未达**目标档**，达档后统一转待发货 |
| 数据 | 团失效 / 取消 | 订单转「已取消（已退款）」，退款进度在团页 | 【已实现】所在团未成团或已取消，款项原路退回（3 个工作日） |
| 数据 | 部分参团人未付款 | 订单各自独立（未付款不生成订单） | — |
| 操作 | 取消未填原因 | 拦截 | 【已实现】取消原因必填（将触发退款流程） |
| 数据 | 无匹配订单 | 空态 | 「暂无匹配的拼单订单」 |

### 1.9 通知与消息

| 事件 | 接收人 | 渠道 | 抑制条件 |
|---|---|---|---|
| 成团 | 全部参团人 | 站内 + 推送 | 一次 |
| 未成团（全额退款） | 全部参团人 | 站内 + 短信 | 一次 |

### 1.10 验收标准

| 编号 | 前置 | 操作 | 预期 | 级别 |
|---|---|---|---|---|
| AC-07 | 成团 6 人 | 查看订单数 | **生成 6 笔订单**（与团页参团人数一致），参团人明细 6 行 + 合计 | P0 |
| AC-08 | 同上 | 查看单价 | 等于所在档单价（成团锁档），不是原价 | P0 |
| AC-09 | 团进行中（未达档） | 查看本页 | 每个参团人各 1 笔「待成团」订单；抽屉提示达档后转待发货（v1.1） | P0 |
| AC-09b | 团已失效 / 已取消 | 查看本页 | 订单为「已取消」，抽屉可点团号跳到团页看退款记录与重试 | P0 |
| AC-10 | 待成团订单 | 专员点取消 | 无按钮（仅主管） | P1 |
| AC-11 | 主管取消并填原因 | 提交 | 本单状态已取消，触发本单退款；团状态不变（整团退款走团管理） | P1 |
| AC-12 | 从团管理点「查看订单」 | 打开本页 | 自动按 `?tid=团号` 筛出该团全部订单，顶部显示来源提示条 | P1 |
