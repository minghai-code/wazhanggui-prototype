## 1. 拼单团管理 `mall-group-manage.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | **团维度**监管拼单活动：团状态、进度、取消全团、退款记录与重试 |
| 使用角色 | 商城运营专员、运营主管 |
| 入口 | 菜单 → 商城运营 → 订单管理 → 拼单团管理 |
| 前置 | 商户商品已配置 `groupEnabled` 与阶梯价（Y-1：配置主体是商户，运营监管） |
| 后置 | 取消 → 全员退款 3 个工作日；成团 → 逐笔生成 GB 订单（跳「拼单集采订单」页） |

> **与「拼单集采订单」页的分界**：那一页是**逐笔订单**（每个参团人一条），本页是**团**（一条团一行）。订单页可跳团详情，本页取消/退款影响整团。

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 买家端拼单发起 / 参团（本页**无新建入口**——拼单只由买家发起，M01 BR-1） |
| 本页操作的跨端影响 | 取消全团 → 全部参团人收到通知 + 全额原路退款；端上参团记录置「已退款」 |
| 依赖的其他端页面 | 买家端拼单详情页 / 拼单集采订单页（10b） |
| 不涉及的端 | 商户端（拼单配置在「新增商品」页，Y-1） |
| 一致性要求 | 成团判定以后台为准（累计达任一档即成团）；**已成团不可取消** |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| **统计卡（4）** | 进行中 / 已成团（逐笔生单）/ 已失效（已退款）/ 已取消（退款中或已退） |
| 筛选区 | 状态（四态）+ 团号 / 商品名称 + 查询 + 重置 |
| 团列表 | **10 列**：团号 · 商品 · 档位 · 起拼档 · 团长下单 · 累计/人数 · 进度（达起拼档%）· 截止时间 · 状态 · 操作 |
| 抽屉 | 团信息 + 成团结算说明 / 取消全团记录 + 退款记录（失败可重试） |

### 1.4 团状态机（分册 §5.1，含 M01 §8.3 缺失的「已取消」）

```
进行中 ──(累计达任一档)──→ 已成团 ──(锁档结算，逐笔 GB 订单)──→ 终局
   ├──(到期未达起拼档)──→ 已失效 ──→ 全额退款 3 个工作日
   └──(团长取消 / 平台强制)──→ 已取消 ──→ 全员全额退款 3 个工作日
```

### 1.5 字段规格

| 列 | 字段 | 说明 |
|---|---|---|
| 团号 | `groupId` | `T` + 年月日 + 3 位流水 |
| 商品 / 档位 | `goods` / `tier` | 档位 = 起始–结束数量 · 单价 |
| 起拼档 | `minTier` | 达到即成团（最小档起始数量） |
| 团长下单 | `leadQty` | 支付首笔即进入「进行中」（BR-4：支付 ≠ 成团） |
| 累计 / 人数 | `cum` / `people` | 进度 = `cum ÷ minTier`（达 100% 即成团） |
| 状态 | `state` | 四态 |
| 退款 | `refund` | 涉及人数 · 金额 · 状态（成功 / 失败挂起可重试） |

### 1.6 主要操作

| 操作 | 可用条件 | 说明 |
|---|---|---|
| **取消全团** | 状态 = 进行中 | 原因必填（通知全部参团人）→ 全员全额退款 3 个工作日；已成团**拦截**（M-06） |
| 退款重试 | 退款记录有失败项 | 重试后失败清零，状态转「已退」 |
| 详情 | 全部 | 团信息 + 结算/取消/退款记录 |

### 1.7 业务规则

| 编号 | 规则 | 依据 |
|---|---|---|
| R-G1 | 取消全团仅限「进行中」；已成团不可取消 | 分册裁决一 / M-06 |
| R-G2 | 团长退出 ≠ 取消全团：退出份额保留、不解散（FR-24） | 分册裁决一 |
| R-G3 | 退款 SLA：3 个工作日原路退回 | M01 Q4 / FR-23 |
| R-G4 | 参团下限 = `ceil(minQty × 20%)`，10 的倍数；与 `tier[0].min` 无关 | 分册裁决二 |
| R-G5 | 成团 → 逐笔生成 GB 订单（`sourceGroupId` 溯源） | M01 FR-22 |
| R-G6 | 本页无新建入口（拼单只由买家发起） | M01 BR-1 |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 交互 | 成团后点取消 | 拦截 | 【已实现】该团已成团并锁定结算，不可取消；如需处理请走售后（M-06） |
| 交互 | 取消原因未填 | 拦截 | 取消原因必填（会通知全部参团人） |
| 数据 | 退款失败 | 挂起，可重试 | 失败原因：{原因}；重试后状态清零 |

### 1.9 验收标准

| 编号 | 前置 | 操作 | 预期 | 级别 |
|---|---|---|---|---|
| AC-G1 | 团进行中 | 取消全团（填原因） | 状态转已取消，产生退款记录，badge 更新 | P0 |
| AC-G2 | 团已成团 | 尝试取消 | 拦截 M-06 | P0 |
| AC-G3 | 退款有失败项 | 点重试 | 失败清零，状态转「已退」 | P0 |
| AC-G4 | 输入团号 / 商品关键字 | 查询 | 精确过滤；重置恢复全量 | P1 |
