## 1. 资料变更审核 `merchant-change.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 审核商户提交的经营信息 / 资质变更，**通过后回写主档并留痕** |
| 使用角色 | 商户管理专员、运营主管 |
| 入口 | 菜单 → 商户管理 → 资料变更审核 |
| 前置 | 商户已在商户端提交变更申请 |
| 后置 | 主档更新；资质类变更联动刷新有效期与报价权限 |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 商户端 ② 主档变更 `shanghu-verify.html → profile-edit.html`；③ 展示信息变更 `my-shops.html → shop-info-edit.html`，**共用一个审核台账 `sh_change_apply`** |
| 本页操作的跨端影响 | 通过 → 回写商户端主档 / 对应档口展示信息；展示信息类 → **买家端「市场导览」按新值生效**；资质类 → 报价权限状态同步；驳回 → 原因推送商户端 |
| 依赖的其他端页面 | `shanghu-APP/profile-edit.html`（② 主档）、`shanghu-APP/shop-info-edit.html`（③ 展示信息）、`shanghu-APP/my-shops.html`（提交入口） |
| 不涉及的端 | ① 账号个人资料（统一账号体系，仅头像 / 昵称 / 邮箱自助保存即生效；**手机号 / 姓名 / 身份证只读**，手机号换绑属账号安全流程、不进本审核；合同侧签署手机号由 05 合同专员人工改绑并留痕）、④ 线上店铺信息（归 10 商城运营） |
| 一致性要求 | 主档 / 展示信息回写留痕（前后值 + 人 + 时间）；展示信息审核通过前买家端仍展示原值；原型以 `sh_shop_display_v1` 回写供商户端回显 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「资料变更审核」+ 导出 |
| **统计卡** | 待审核变更 / 本月通过 / 本月驳回（各带副值：待审核 / 已通过 / 已驳回计数） |
| 筛选区 | 关键词（商户名称 / 变更编号 / **档口编号**）+ 变更类型（**5 类**）+ 状态 + 商户类型 + 日期区间 + 查询 + 重置 |
| 列表 | **8 列** + 分页；「店铺展示信息」行的摘要前置「档口 {编号}」标签 |
| 审核抽屉 | 变更主体（含**关联档口**）+ 变更前后对比表（**3 列**：字段 / 变更前 / 变更后）+ 通过后的连锁动作 + 通过 / 驳回 |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 提交时间倒序 |
| 分页 | 页码 |
| 筛选组合 | 条件之间 **且** |
| 变更类型 | **5 类**：企业信息 / 联系方式 / 资质 / 经营类目（② 主档）+ **店铺展示信息**（③ 线下实体档口展示信息）。已移除「商位」；**① 个人资料、④ 线上店铺信息不进本审核** |
| 状态 | 待审核 / 已通过 / 已驳回 |
| 关键词 | 除商户名称 / 变更编号外，支持按**档口编号**筛出该档口的展示信息变更（从商户档案 ⑩ 深链进入） |
| 空结果 | 暂无匹配的变更申请 |

### 1.5 字段规格

**变更列表（8 列）**

| 列 | 字段 | 说明 |
|---|---|---|
| 变更编号 | `id` | 点击进详情 |
| 商户名称 | `merchantName` | 点击跳 P3 档案 |
| 商户类型 | `merchantType` | 仅线上 / 线上兼档口 / 仅线下档口 |
| 变更类型 | `type` | **五类枚举**（含「店铺展示信息」） |
| 变更内容摘要 | `diff` | **前后值对比**，多字段折叠；展示信息类前置档口编号 |
| 提交时间 | `submitAt` | — |
| 状态 | `state` | 待审核 / 已通过 / 已驳回 |
| 操作 | — | 审核 / 详情 |

**前后对比（3 列）**：字段 / 变更前 / 变更后

**「店铺展示信息」字段（与 `shanghu-APP/shop-info-edit.html` 同口径）**

| 可申请变更字段 | 说明 |
|---|---|
| 店铺名称 / 商铺简介 / 营业时间 / 联系电话 / 营业状态 / 市场导览可见 | 逐字段提交，每条申请带 `unit=档口编号`；通过后只回写**该档口**对应字段 |
| 门店图 | 作为证明材料随申请上传，抽屉内可预览 |

> 只读字段不可变更：**身份证、商户编号、商户类型、关联档口、档口面积 / 租期 / 合同、经营品类**（品类走主档变更审核，通过后展示信息只读派生自动更新）。线上店铺信息归 10 商城运营，不受理。

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 审核 | 状态=待审核 | 专员/主管 | 抽屉（档口编号 + 前后对比 + 连锁动作 + 备注） | — |
| 通过 | 待审核 | 专员/主管 | 回写主档 / 对应档口展示信息 + 留痕 + 通知商户 | — |
| 驳回 | 待审核 | 专员/主管 | 必须选原因（字典 + 备注），原因推送商户端 | 未选 → M-11 |
| 查看门店图 | 类型=店铺展示信息 | 始终 | 预览门店图 / 展示信息截图 | — |
| 详情 | 始终 | 始终 | 只读抽屉 | — |
| 查看商户档案 | 抽屉底部 | 始终 | 跳 `merchant-profile.html?kw={商户名}` 并打开详情 ⑩ | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-07 | 通过即回写主档 | 通过 | 前后值 + 操作人 + 时间入留痕 | 商户端 |
| R-08 | 资质类变更联动 | 通过（类型=资质） | 刷新资质有效期 → 报价权限状态同步 | 商户端、10a |
| R-09 | 驳回原因必填 | 驳回 | 字典 + 自由备注 | 商户端 |
| R-10 | 只读字段过滤 | 提交 | 身份证/编号/类型/档口/面积/租期/合同不进变更集；展示信息页的经营品类只读 | — |
| R-11 | 同一字段在途唯一 | 提交 | **商户 + 档口 + 字段** 三元组只允许一条待审核；同档口不同字段、不同档口同字段可并行 | 商户端 |
| R-18 | 展示信息通过后回写 | 通过（类型=店铺展示信息） | 只回写**该档口**对应展示字段 + 留痕；买家端「市场导览」按新值生效；商户端按 `unit` 回显 | 商户端、买家端 |
| R-19 | 审核前展示原值 | 待审核 | 展示信息变更提交后**不立即生效**，商户端与买家端仍展示变更前的值 | 商户端、买家端 |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 数据 | 驳回未选原因 | 拦截 | 【已实现】「驳回原因必填，请先选择」 |
| 数据 | 列表为空 | 空态 | 暂无匹配的变更申请 |
| 数据 | 同商户 + 档口 + 字段重复提交 | 商户端拦截，只保留一条在途（R-11） | — |
| 数据 | 展示信息变更在途 | 商户端 / 买家端仍展示变更前的值（R-19） | — |
| 权限 | 非专员点审核 | 按钮隐藏 | — |
| 并发 | 两人同时审同一条 | 后者收到冲突 | **【待实现】M-48** |
