## 1. 租金催缴 `merchant-dunning.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 每年 8 月 15 日起自动催缴第二年租金；**已缴的不再打扰** |
| 使用角色 | 商户管理专员（日常）、运营主管（规则配置审批） |
| 入口 | 菜单 → 商户管理 → 租金催缴 |
| 前置 | 05 合同有应收计划；财务提供累计已缴名单 |
| 后置 | 通知已发；缴纳状态更新；下次扫描自动跳过已缴 |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 05 合同应收计划（金额）+ 财务线下台账（累计已缴）+ 人工登记 |
| 本页操作的跨端影响 | 发送 → 商户端站内 + 微信（含短信可选）；暂停 → 该户不再收通知 |
| 依赖的其他端页面 | `shanghu-APP/payment.html`（账单展示） |
| 不涉及的端 | 买家端 |
| 一致性要求 | **发送前三重校验**：已缴名单 + 合同状态 + 暂停标记 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「租金催缴（自动）」+ 导出 + 缴纳名单导入 + 手动触发扫描 + 规则配置 |
| **统计卡** | 应催商户数（2026）/ 应收总额 · 已缴 / 已缴清 / 催缴中（未缴 · 部分缴）/ 今日实发通知 |
| 筛选区 | 关键词 + 租赁年度 + 缴纳状态 + 通知次数 + 查询 + 重置 |
| 催缴台账 | **8 列** |
| **缴纳名单导入** | 模板下载 + 上传 Excel + 预校验结果表（**4 列**）+ 批次记录表（**8 列**） |
| 规则抽屉 | 催缴期 / 频率 / 时段 / 逾期升级 / 渠道 / 文案 |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 未缴金额降序 |
| 分页 | 不分页（原型单页） |
| 筛选组合 | 条件之间 **且** |
| 缴纳状态 | 未缴 / 部分缴 / 已缴清 |
| 空结果 | 「本轮无可催缴商户」 |

### 1.5 字段规格

**催缴台账（8 列）**

| 列 | 字段 | 说明 |
|---|---|---|
| 租赁年度 | `year` | 如 2026 |
| 商户 / 档口 | `merchant` / `unit` | — |
| 合同号 | `contractNo` | 来自 05 |
| 应收 / 已缴 / 未缴 | `due` / `paid` / `unpaid` | 金额，元 |
| 通知次数（站内 · 微信） | `noticeCount` | 分渠道计数 |
| 最近通知 | `lastNoticeAt` | — |
| 缴纳状态 | `payState` | 未缴 / 部分缴 / 已缴清 |
| 操作 | — | 登记缴纳 / 补发 / 暂停 / 恢复 / 详情 |

**导入预校验（4 列）**：商户 / 档口 · 合同号 · 本次累计已缴 · 处理结果（命中 / 未缴足 / 未匹配）

**导入批次（8 列）**：导入时间 · 文件名 · 行数 · 命中 · 未缴足 · 未匹配 · 操作人 · 操作（撤销）

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 手动触发扫描 | 始终 | 专员 | 逐户三重校验 → 实发 | 已缴清户 → M-17 |
| 登记缴纳 | 未缴 / 部分缴 | 专员 | 填本次实缴金额 → 更新状态 | — |
| 导入已缴名单 | 始终 | 专员 | 上传 → 预校验 → 确认 → 已缴户置已缴清 | 未匹配行进清单 |
| 人工补发 | 未缴 / 部分缴 | 专员 | 补发通知（计入次数） | 已缴清 → M-17 |
| 暂停该户 | 未缴 / 部分缴 | 专员 | 停发通知（记原因） | — |
| 恢复催缴 | 已暂停 | 专员 | 恢复发送 | — |
| 规则配置 | 始终 | 主管 | 催缴期 / 频率 / 时段 / 渠道 / 文案 | 开始日为空 → M-21 |
| 撤销批次 | 有批次 | 专员 | 撤销该次导入（状态回滚） | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-34 | 每年 8/15 起催缴次年租金 | 定时 | 规则可配 | 商户端 |
| R-35 | **发送前三重校验** | 发送 | ① 已缴名单 + 人工核销 ② 合同状态（终止/到期不发）③ 暂停标记 | 商户端 |
| R-36 | 已缴清不再通知 | 校验 | 直接跳过，不计次数 | 商户端 |
| R-37 | 未缴足按差额更新 | 导入 | 更新已缴金额与状态 | 商户端 |
| R-38 | 未匹配行进清单 | 导入 | 不自动置已缴清，人工核对 | — |
| R-39 | 渠道 = 站内 + 微信（短信可选） | 发送 | 短信需独立服务，2026-10-09 暂缓 | 商户端 |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 数据 | 补发已缴清商户 | 拦截 | 【已实现】「该商户已缴清：系统已停止催缴（无需补发）」 |
| 数据 | 催缴开始日为空 | 拦截 | 【已实现】「请填写催缴开始日」 |
| 数据 | 导入有未匹配行 | 单独列出待人工核对 | 【已实现】「已导入累计已缴名单：…」 |
| 依赖 | 微信未绑定 | 只发站内 | — |
| 数据 | 合同已终止/到期 | 跳过不发送 | — |

### 1.10 验收标准
