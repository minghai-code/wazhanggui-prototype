1. 资质与到期管理 merchant-qual.html

1.1 页面说明

项内容
页面目标管理企业资质与证书有效期：过期自动冻结报价，重传后复核解冻
使用角色商户管理专员（复核）、运营主管（终审）
入口菜单 → 商户管理 → 资质与到期管理
前置商户已在商户端提交/重传资质
后置通过 → 报价权限恢复；过期 → 自动冻结
定位（2026-10-08 口径修正）：资质不再是报价的前置门槛——报价权限随入驻审核默认开通。本页只做两件事：到期复核 + 受限场景校验（品牌授权类 / 大额询价 / 需质检报告的品类）。

1.2 本页端间关系

项内容
本页数据来源shanghu-APP/shanghu-verify.html 提交 / 重传；主体认证可运营端代录（线下收证件）
本页操作的跨端影响台账通过 → 商户端"我的"显示认证标识 + 报价可用；过期 → 端上报价报错提示需重传。主体认证通过 → 买家端「政策申报 / 技术共享」入口开放；驳回/未提交 → 端上显示「需企业资质」
依赖的其他端页面shanghu-APP/shanghu-verify.html；买家端 policy-service.html / tech-service.html（只读本页认证结果）
不涉及的端除上述入口外的买家端功能
一致性要求到期冻结对 10a 询价即时生效；主体认证结果与 13 产业链申报准入同源判定，不重复定义

1.3.1 主体认证 Tab（2026-10-28 新增）

为什么加：13 产业链服务的「政策申报 / 技术共享」要求已绑定且认证通过的商户主体（13 分册 v1.5），买家端据此决定显示「需企业资质」还是放开入口。而资质台账是证书维度（一张执照一条记录），回答不了「这家商户整体认证到什么程度」。故补一层商户维度的认证状态。 两套状态互不替代：台账管「这张证到期没到期」，主体认证管「这家商户能不能申报政策」。不要用台账状态推导申报准入。
列说明
商户名称关联 04 商户档案
主体类型个体工商户 / 企业 / 工厂制造商（沿用档案口径）
主体性质个人（个体工商户）/ 企业（企业、工厂制造商）
证件编号统一社会信用代码 / 身份证号
提交 / 审核时间未提交显示「—」
认证状态未提交 / 审核中 / 已通过 / 已驳回
政策申报准入已通过 → 可申报；审核中 → 暂不可；已驳回 → 关闭待重传；未提交 → 端上显示「需企业资质」

状态流转：未提交 →（商户提交 / 运营代录）审核中 → 已通过 / 已驳回；已驳回 →（重传）审核中。

驳回原因必填，字典：营业执照主体与经营者不一致 / 证件不清晰缺页 / 证件已过期 / 主体类型选择错误 / 其他。

准入口径：只认「已通过」，当前不区分个人与企业（个体工商户持营业执照即视为具备企业资质）。如需收紧为「仅企业 / 工厂制造商可申报」，加一条类型校验即可。
