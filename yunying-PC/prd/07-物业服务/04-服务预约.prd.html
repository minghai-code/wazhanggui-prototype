1. 服务预约 property-service.html

1.1 页面说明

项内容
页面目标商户预约单的受理、派单、执行跟踪、评价与回访；订单聚合处理、分配人员分流处置（招标 #129）
使用角色物业客服（受理 / 派单 / 代录 / 费用登记）、运营主管（回访）、物业人员（员工端打卡，本页只读跟踪）
入口菜单 → 物业服务 → 服务预约
前置商户端已提交预约（sh_booking），或客服电话代录
后置回写商户端（状态 / 师傅 / 费用 / 评价）；费用线下结算，不进维修资金台账、不生成账单

1.2 本页端间关系

项内容
本页数据来源商户端 service-booking.html 提交的 sh_booking（shared/wuye-sync.js 注入）；客服电话代录
本页操作的跨端影响受理 → 商户端显示「已受理」+ 师傅 + 上门时间；驳回 → 商户端显示「已取消」+ 原因；完成打卡 → 商户端「已完成」；回写保留 unit
依赖的其他端页面shanghu-APP/service-booking.html（预约提交 / 列表）、shanghu-APP/wuye-service.html（员工端打卡拍照；端上页面未建，待办 #58）
不涉及的端买家端
一致性要求回写保留 unit（上报档口）；评价 ≤3 星自动标「需回访」并通知主管

1.3 页面结构

区块内容
顶部标题「服务预约」+ 电话代录预约 + 导出
统计卡（6）待确认 · 已受理 · 异常待处理 · 今日预约 · 需回访（≤3 星）· 本月已完成
状态筛选筛选区「全部状态」下拉：待确认 / 已受理 / 异常待处理 / 已完成 / 已取消，选项带各态数量（如「待确认（3）」），与其他筛选控件一致；不使用平铺 Tab 条
筛选关键词（编号 / 档口 / 商户 / 内容）+ 服务类型 + 来源 + 仅看需回访（选项由数据动态生成，见 v1.8 附节）
列表（10 列）预约编号（带提交时间小字）· 来源 · 上报档口 · 商户（带电话）· 服务类型（带内容摘要）· 预约时间 · 师傅（带到场 / 预计）· 评价（星级 + 需回访）· 状态 · 操作
详情抽屉7 段：预约信息 / 受理与派单 / 执行留痕（打卡拍照）/ 现场异常（员工端上报） / 费用（线下结算）/ 商户评价 / 流程时间轴

1.4 字段规格

预约单（YY）字段

字段说明
no单号 YY2026MM-XXXX（商户端生成；代录同前缀）
src商户端 / 电话代录
unit上报档口（单据归属），一张单只归属一个档口
type保洁 / 维修 / 搬运（三类，招标口径与商户端一致）
name服务内容（≥4 字）
time预约时间 预约 YYYY-MM-DD HH:mm-HH:mm（商户端原样；代录由日期选择器 + 时段拼装，日期限今天起 30 天内）
state待确认 → 已受理 → 已完成；已受理 → 异常待处理（师傅现场上报）→ 改派 / 重新排期回「已受理」、取消 → 「已取消」；待确认 / 已受理可 → 已取消
worker / planAt师傅 / 预计上门（受理派单时产生，可改派）
arriveAt / arriveGeo师傅到场打卡：时间 + GPS 定位（员工端提交）
finishAt / resultDesc完成打卡：时间 + 处理说明（员工端提交）
fee / feeNote / feeSettled费用选填，线下结算；不进维修资金台账、不生成账单
star / comment商户评价：星级 1–5 + 留言必填；≤3 星标「需回访」
visitAt / visitBy / visitNote回访闭环：登记时间 / 回访人 / 回访记录；有 visitAt 即「已回访」，不再计入「需回访」
cancelWhy驳回 / 取消原因（必填）
exceptionWhy / exceptionNote / exceptionAt / exceptionGeo / exceptionPhotos现场异常（第 5 态）：原因（6 项字典，必填）/ 补充说明 / 上报时间 / 上报定位 / 现场照片，由员工端「上报异常」写入，后台只读并可据此改派 / 重新排期 / 取消

「需回访 / 已回访」口径（不是独立状态，是已完成单上的标记）

项规则
需回访state=已完成 + star>0 && star<=3 + 未登记回访（visitAt 为空）→ 评价列红字「需回访」，操作出现「登记回访」，统计卡「需回访（≤3 星）」计入
已回访同上但 visitAt 有值 → 评价列绿字「已回访」，操作变「再次回访」，不再计入统计卡
前置条件只有「已完成 + 已评价 + ≤3 星」可登记；4–5 星不需要回访、未完成 / 未评价单不可登记（拦截提示）
登记内容回访人（默认运营主管）+ 回访记录必填 → 写 visitAt / visitBy / visitNote + 时间轴留痕「主管回访…（「需回访」已闭环）」
再次回访已回访单可追加记录，只追加留痕、不重复计数
为什么有低分评价的满意度闭环动作（与投诉建议页「≤3 星自动回访」同口径），不改变预约单状态

状态机（5 态，v1.5 新增「异常待处理」）

stateDiagram-v2
    [*] --> 待确认: 商户端提交 / 电话代录
    待确认 --> 已受理: 受理并派单（师傅 + 预计上门）
    待确认 --> 已取消: 驳回（原因必填）
    已受理 --> 异常待处理: 师傅现场上报异常（员工端，原因必填 + 定位）
    异常待处理 --> 已受理: 改派（新师傅 + 新预计上门）／重新排期（原师傅，新时间）
    异常待处理 --> 已取消: 取消预约（原因必填）
    已受理 --> 已取消: 驳回
    已受理 --> 已完成: 员工端完成打卡（自动回写）
    已完成 --> [*]: 评价（≤3 星 → 需回访 → 主管登记回访闭环）
    已取消 --> [*]: 商户可重新预约
师傅执行动作在员工端（wuye-service.html，端上页面已建，商户端待办 #59）：今日预约 → 到场打卡（时间 + GPS）→ 完成打卡（处理说明 + 照片）；现场无法服务时「上报异常」（原因 6 项 / 说明 / 照片 / 定位）→ 单据进入「异常待处理」，由本页改派 / 重新排期 / 取消。本页只读跟踪执行动作，不在运营端代打卡。
