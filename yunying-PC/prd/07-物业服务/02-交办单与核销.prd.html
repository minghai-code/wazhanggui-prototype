端：运营端 PC（yunying-PC）　｜　模块：07 物业服务（分册 §8.3） 页面：property-request.html　｜　页面版本：v1.0（2026-10-27） 前置：01-报修工单.md（含模块通用说明 §0，编号/权限/审批链/硬校验规则见该篇）

1. 页面定位

本模块最核心的一页。它把"零散报修 → 攒批采购 → 审批 → 发票核销 → 额度扣减"串成可审计的链。

  • 使用者：物业专员（建单/核销）、各级审批人（审核）
  • 上游：P1「需物料」的报修单汇入待采购池
  • 下游：核销金额回流 P3 额度台账；异常进核销异常台账

4. 交办单状态机（6 态）

stateDiagram-v2
    [*] --> 草稿: 存草稿（不占额度、不进审批）
    草稿 --> 待审核: 提交审核
    待审核 --> 待审核: 通过 → 下一节点
    待审核 --> 已驳回: 驳回（版本 +1，重提从第一级）
    已驳回 --> 待审核: 修改后重提
    待审核 --> 已通过: 终审通过 → 可采购
    已通过 --> 部分核销: 上传凭证（未核完）
    已通过 --> 已核销完成: 上传凭证（全部核完）
    部分核销 --> 部分核销: 继续核销
    部分核销 --> 已核销完成: 核完
    已通过 --> 已核销完成: 申请结项（放弃剩余）

当前节点字段：待审核时显示审批节点名（市场管理部 / 市场部负责人 / 分管领导 / 董事长）；已通过显示「已通过 · 可采购」；核完显示「已归档 · 核销完成」。

字段必填校验

5.2 物资明细（逐行）

物资名称 · 规格 · 数量 · 单价 · 小计（自动）· 供应商

数量与单价是核销的比对基准：核销时逐行比对"累计数量 ≤ 审批数量"、"单价 ≤ 审批单价 ×1.1"。

6. 核销（本模块最核心机制）

6.1 三步操作

  1. 勾选本次采购的物资行（默认预勾未核完的行，可勾部分数量）
  2. 填发票：发票号 / 开票日期 / 供应商 / 发票金额 / 其他费用（运费·税费·折扣）/ 凭证附件
  3. 看实时校验，提交

6.2 五项校验（分级）

#校验级别表现
C1未勾选物资行硬拦请至少勾选 1 行物资明细
C2要素不全（发票号/日期/供应商/金额/附件）硬拦对应提示
C3发票号重复硬拦发票号 {inv} 已用于核销，不可重复提交
C4累计数量 > 审批数量标异常生成 YC 超核，核销照常成功
C5单价 > 审批单价 ×1.1标异常生成 YC 单价偏高
C6累计金额 > 审批金额标异常生成 YC 金额超审批
C7供应商与审批时不同标异常生成 YC 换供应商
C8额度不足阻断提示跳 P3 申请追加
C9明细+其他费用 ≠ 发票金额标异常实时提示差额，仍可提交

6.3 核销后状态推进

条件结果
全部物资行 已核 ≥ 审批已核销完成，节点「已归档 · 核销完成」
仍有未核完行部分核销，节点仍「已通过 · 可采购」

7. 审批（审核人视角）

抽屉分四段，不是简单点通过：

段内容
① 报修真实性显示关联报修单号，可点进看现场照片与处理后照片
② 物资明细与价格参考每行显示 历史中位价 与 偏离百分比（>30% 标红）
③ 比价充分性供应商列表 + 附件下载
④ 审批链已走过的节点与意见

通过 → 推进下一节点；驳回 → 原因必填（≥4 字），版本 +1，重提从第一级开始。

8. 异常台账处置

动作说明
接受说明认可以偏差（如原料涨价），留原因
要求补正退回要求补材料
追回差额从结算中扣减

处置说明必填（≥4 字），写入台账留痕。
