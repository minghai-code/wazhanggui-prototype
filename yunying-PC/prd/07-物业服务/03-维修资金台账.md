## 1. 页面定位

一眼看清"**今年 25 万花了多少、还剩多少、花在哪**"，并管住超额申请。

- 使用者：财务（核对）、物业主管（发起申请）、董事长（看额度红线）
- 上游：P2 核销成功金额 → 计入「已核销」；P2 已通过未核销 → 计入「在途」
- 下游：额度不足时阻断 P2 核销，引导到这里申请追加

## 3. 额度看板口径

| 卡 | 口径 | 预警 |
|---|---|---|
| 年度总额度 | `base + carry + extra`（基础 **250,000** + 上年结转 + 追加） | — |
| **上年结转** | 上年总额度 − 上年已核销 − 上年跨年在途；副标题显示来源年度；**点卡片打开「结转口径」说明抽屉** | 结转 > 基础额度 100% 时提示（上限待确认） |
| 已核销 | Σ **核销成功**金额 | — |
| 在途 | Σ（已通过 / 部分核销单的 `审批金额 − 已核销`）；**按年度归集**，只算核销当年 | — |
| **剩余** | `总额度 − 已核销 − 在途` | **<20% 橙色；<0 红色「已超支」** |
| 额外追加 | Σ 已通过的额外申请金额 | — |

> **BD-2**：只有「核销成功」才计入已核销；**审批通过只算在途**，不占已核销。
> **BD-1**：额度周期 = **额度年度 4.1 – 次年 3.31**（客户 2026-10-29 确认，非 9.1–8.31）。年度标签显示为 `2026.04–2027.03`。
> **BD-1a**：**上年没用完的额度结转下一年继续用**（客户 2026-10-29 确认，推翻原"每年清零"）。结转额 = 上年总额度 − 上年已核销 − 上年跨年在途。
> **BD-1b**：上年审批通过、本年才核销的单子**扣核销当年额度**，已在上年结转时扣除，不重复占额。
> **BD-1c**：结转**逐年累计**；是否设上限**待客户确认**（累计不封顶 / 最多结转 1 年 / 不超过年度额度 1 倍），原型按不封顶呈现。

## 5. 待核销清单

| 列 | 说明 |
|---|---|
| 交办单号 / 项目名称 / 审批金额 / 已核销 / **待核金额** / 提交时间 / **停留** / 操作 |

**停留 > 15 天**标红「久悬」——跨期未核销会在**核销当年**扣额度，等于推迟到次年才真正花掉，且已在上年结转时先被扣减，两边都要留意。

## 6. 额外申请

### 6.1 申请字段

| 字段 | 必填 | 校验 |
|---|---|---|
| 申请金额 | 是 | **>0** |
| 用途说明 | 是 | **≥10 字** |
| 依据附件 | 否 | 报价单 / 说明文件 |
| 申请人 / 时间 | 自动 | — |

### 6.2 审批链（串行 2 级）

`运营主管 → 财务`

- 运营主管通过 → 节点转「财务」，**额度尚未追加**
- 财务通过 → **追加到当年总额度**，留痕（申请人 / 审批人 / 金额 / 原因）
- 驳回 → 原因必填（≥4 字），额度不追加

> **BD-3**：额外申请通过后追加到**当年**总额度；当年度未用完的部分**结转下一年继续用**。

## 7. 历史采购导入

| 项 | 内容 |
|---|---|
| 模板列 | 物资名称 / 规格 / 数量 / 单价 / 供应商 / 采购日期 / 发票号（可空） |
| 校验 | **物资名称与单价必填**；单价 >0；日期格式 `YYYY-MM-DD` |
| 失败处理 | **整批回滚** + 失败行清单（每行标具体错误） |
| 导入后 | 写入**历史成交价库**（作为 P2 单价偏离校验的基准） |

> **BD-5**：历史采购导入**不影响额度**（历史年度已花掉），仅用于价格基准。
