## 1. 页面定位

一眼看清"**今年 30 万花了多少、还剩多少、花在哪**"，并管住超额申请。

- 使用者：财务（核对）、物业主管（发起申请）、董事长（看额度红线）
- 上游：P2 核销成功金额 → 计入「已核销」；P2 已通过未核销 → 计入「在途」
- 下游：额度不足时阻断 P2 核销，引导到这里申请追加

## 3. 额度看板口径

| 卡 | 口径 | 预警 |
|---|---|---|
| 年度总额度 | `base + extra`（合同约定 300,000 + 追加） | — |
| 已核销 | Σ **核销成功**金额 | — |
| 在途 | Σ（已通过 / 部分核销单的 `审批金额 − 已核销`） | — |
| **剩余** | `总额度 − 已核销 − 在途` | **<20% 橙色；<0 红色「已超支」** |
| 额外追加 | Σ 已通过的额外申请金额 | — |

> **BD-2**：只有「核销成功」才计入已核销；**审批通过只算在途**，不占已核销。
> **BD-1**：额度周期 = 租赁年度 9.1–8.31，**跨期不结转**。

## 4. 结构分析口径

| 块 | 口径 | 备注 |
|---|---|---|
| 物资类别 TOP10 | 按核销明细的物资类别汇总金额，降序 | 展示前 10，带占比条 |

## 5. 待核销清单

| 列 | 说明 |
|---|---|
| 交办单号 / 项目名称 / 审批金额 / 已核销 / **待核金额** / 提交时间 / **停留** / 操作 |

**停留 > 15 天**标红「久悬」——跨期未核销会挤占下一年度额度。

## 6. 额外申请

### 6.1 申请字段

| 字段 | 必填 | 校验 |
|---|---|---|
| 申请金额 | 是 | **>0** |
| 用途说明 | 是 | **≥10 字** |
| 依据附件 | 否 | 报价单 / 说明文件 |
| 申请人 / 时间 | 自动 | — |

### 6.2 审批链（串行 2 级）

`运营主管 → 财务`

- 运营主管通过 → 节点转「财务」，**额度尚未追加**
- 财务通过 → **追加到当年总额度**，留痕（申请人 / 审批人 / 金额 / 原因）
- 驳回 → 原因必填（≥4 字），额度不追加

> **BD-3**：额外申请通过后追加到**当年**总额度，跨期不结转。

## 7. 历史采购导入

| 项 | 内容 |
|---|---|
| 模板列 | 物资名称 / 规格 / 数量 / 单价 / 供应商 / 采购日期 / 发票号（可空） |
| 校验 | **物资名称与单价必填**；单价 >0；日期格式 `YYYY-MM-DD` |
| 失败处理 | **整批回滚** + 失败行清单（每行标具体错误） |
| 导入后 | 写入**历史成交价库**（作为 P2 单价偏离校验的基准） |

> **BD-5**：历史采购导入**不影响额度**（历史年度已花掉），仅用于价格基准。

## 9. 验收要点

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-01 | 待核销清单 | 金额等于 P2 已通过未核销的合计（口径一致） |
| AC-02 | 核销一笔后回看 | 已核销 ↑、在途 ↓、剩余不变（总额度不变） |
| AC-03 | 额外申请走完 2 级 | 总额度 = 原额度 + 申请金额，额外追加卡同步 |
| AC-04 | 运营主管通过后 | 节点转「财务」，**额度未变**（不能提前加） |
| AC-05 | 导入含 1 行失败 | **整批回滚**，提示 0 行入库，列出失败行 |
| AC-06 | 剩余低于 20% | 剩余卡变橙色；低于 0 变红色「已超支」 |
| AC-07 | 切换年度 | 全部看板与结构分析同步切换 |
