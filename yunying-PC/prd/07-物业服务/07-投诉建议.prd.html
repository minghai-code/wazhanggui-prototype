1. 页面定位

收敛商户与买家的不满，并通过转单反哺物业闭环：

  • 维修质量 → 转报修（BX）
  • 秩序问题 → 转整改（ZG）
  • 使用者：客服 / 物业专员（受理 / 回复）、物业主管（升级处理）
  • 上游：商户端 App、买家端 App、电话代录、巡检转
  • 下游：P1 报修、P7 整改

4. 状态机（5 态）

stateDiagram-v2
    [*] --> 待受理: 商户端/买家端/电话代录/巡检转
    待受理 --> 已升级: 超 24h 未受理（自动）
    已升级 --> 处理中: 受理（指定处理人）
    待受理 --> 处理中: 受理
    处理中 --> 已回复: 填回复内容（通知投诉人）
    已回复 --> 已关闭: 已回复且已评价 → 关闭（终态）
    已回复 --> 处理中: 满意度 ≤3 星 → 自动回访

5. 字段分组

分组字段必填
基本信息来源（商户端 / 买家端 / 电话代录 / 巡检转）、投诉人、联系方式、记录人是
对象与分类被投诉对象（商户 / 物业人员 / 公共区域 / 平台）、分类是
内容描述（≥5 字）、照片（选填）描述必填
处理受理人、处理人、回复内容回复时必填
评价满意度 1–5 星、标签、评价内容商户填（端上）
TS-4：来源 = 电话代录 时，联系方式（来电号码）必填，否则无法回访。
