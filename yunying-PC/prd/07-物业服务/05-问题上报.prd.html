07 物业服务 · 05 问题上报

端：运营端 PC（yunying-PC）　｜　模块：07 物业服务（分册 §8.6） 页面：property-issue.html　｜　页面版本：v1.0（2026-10-27） 前置：01-报修工单.md（含模块通用说明 §0）

1. 页面定位

承载巡检发现与外部反馈的现场问题，按责任方分流：商户责任 → 整改（ZG），物业责任 → 转报修（BX），待判定 → 主管判定。

核心分清：问题（WT）不等于报修（BX）。转报修是新建一张 BX 并回写 BX 号到 WT，WT 记录永久保留（WT-1）。
  • 使用者：巡检员（上报）、物业主管（判定责任方 + 分流）
  • 上游：P5 巡检任务上报、商户端 / 买家端 / 电话反馈
  • 下游：P7 整改（ZG）、P1 报修（BX）

4. 状态机（6 态）

stateDiagram-v2
    [*] --> 待判定: 上报时责任方=待判定
    [*] --> 待处理: 上报时责任方=商户/物业
    待判定 --> 待处理: 主管判定责任方
    待处理 --> 已派整改: 派整改（商户责任）→ 生成 ZG
    待处理 --> 已转报修: 转报修（物业责任）→ 生成 BX

    已派整改 --> 已关闭: 关闭（原因必填）
    已转报修 --> 已解决: 报修完成
    已转报修 --> 已关闭: 关闭（原因必填）
    待处理 --> 已关闭: 关闭（重复/无效/已自行处理）
    待判定 --> 已关闭: 关闭（原因必填）

5. 表单字段与校验

字段必填校验
区域（楼栋/楼层 + 档口）是楼栋楼层与具体位置均必填（02 字典）
问题类型是消防 / 卫生 / 占道 / 设备 / 安全
问题描述是≥5 字
现场照片是≥1 张（同 BX 规则，水印含时间·位置·编号）
严重程度是严重 / 一般 / 轻微
责任方是商户责任 / 物业责任 / 待判定
限期商户责任时必填日期（不得早于当日）
责任方选择后，页面即时提示后续路径（派整改 / 转报修 / 需判定）。

6. 分流操作

操作显示条件效果
判定责任方待判定选商户/物业责任 + 判定说明 → 待处理
派整改待处理 + 商户责任生成 ZG 单（带原照片与位置），状态「已派整改」，显示 ZG 号
转报修待处理 + 物业责任生成 BX 单（带原照片与位置），状态「已转报修」，显示 BX 号
改判待处理 / 已派整改 / 已转报修原因必填（≥4 字），留痕；已生成的 ZG/BX 不撤销
关闭除已关闭外任一原因必填（重复 / 无效 / 已自行处理 / 已合并 / 其他）

规则

编号规则
WT-1转报修后原记录保留（不删除、不改类型），仅回写 BX 号
WT-2改判责任方需留痕（原值 → 新值 + 原因）
WT-3待判定超 3 天提醒主管（列表标红「超 N 天」）
WT-4商户责任未设限期不能派整改
