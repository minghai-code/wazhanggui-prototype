## 1. 页面定位

承接**移动端随手报 / 商户端反馈 / 电话代录**的现场问题，判断"这事能不能当场解决"：

- **能当场解决** → 填处理结果 + 处理后照片 → **关闭**（不产生任何下游单）
- **需要专业维修** → **转报修**，进入报修流程（`property-repair.html`）

> **核心分清**：问题（`WT`）≠ 报修（`BX`）。转报修是**新建一张 BX 并回写 BX 号到 WT**，`WT` 记录**永久保留**；转出后本页**只读跟踪**，工单状态由报修页决定，不回写。

- 使用者：物业主管 / 值班人员（判定与处置）
- 上游：移动端（商户端 App 物业身份）、商户端反馈、电话代录
- 下游：报修工单（`property-repair.html`）
- **不做**：商户整改单（`ZG`）已整体下线；不做改判；不做"商户端提交整改 → 复核"

## 4. 状态机（3 态）

```mermaid
stateDiagram-v2
    [*] --> 待处理: 上报即进入（责任方在上报时选定）
    待处理 --> 已关闭: 提交处理结果（说明 + 处理后照片）
    待处理 --> 已转报修: 转报修 → 生成 BX
    已转报修 --> [*]: 后续在「报修工单」闭环，本页只读
```

> **责任方不参与状态流转**：它只是问题身上的一个归因标签，不会让问题"卡在等判定"。

## 5. 表单字段与校验

| 字段 | 必填 | 校验 |
|---|---|---|
| 区域（楼栋/楼层 + 档口） | 是 | 楼栋楼层与具体位置均必填（02 字典） |
| 问题类型 | 是 | 消防 / 卫生 / 占道 / 设备 / 安全 |
| 问题描述 | 是 | **≥5 字** |
| **现场照片** | **是** | **≥1 张**（同 BX 规则，水印含时间·位置·编号） |
| 严重程度 | 是 | 严重 / 一般 / 轻微 |
| **责任方** | **是** | **商户责任 / 物业责任**（默认物业）；**只做归因统计 + 决定要不要通知商户**，不驱动分流、不参与状态流转 |
| 要求处理期限 | 否 | 日期；仅用于超期提醒，不再是"派整改"的前置条件 |

> 责任方选择后，页面即时提示：商户责任 → 需通知商户并留证；物业责任 → 内部处置，必要时转报修。**两者都不影响单据走向**。

## 6. 处置操作（只有两条出口）

| 操作 | 显示条件 | 效果 |
|---|---|---|
| ~~判定责任方~~ | — | **v1.3 删除**：上报时就必须选责任方，不再有"挂起等判定" |
| **提交处理结果** | 待处理 | 处理结果说明 **≥5 字** + **处理后照片 ≥1 张** + 商户告知方式 → 状态转**已关闭**，**不生成任何下游单** |
| **转报修** | 待处理 | 打开转单抽屉，**按报修工单「新增」字段生成 BX**（见下表）→ 状态「已转报修」，回写 BX 号 |

| **修正责任方** | 详情抽屉内，任一状态 | 选两值 + 填原因（≥4 字）→ **只改归因标签**，不改状态、不生成单据、留痕「原值 → 新值 + 原因 + 操作人」 |
| ~~改判~~ | — | **已下线**（2026-11-03）：责任方不再驱动分流，无需改判 |

### 6.1 转报修的字段映射（对齐 `property-repair.html` 新增）

| BX 字段 | 来源 | 说明 |
|---|---|---|
| `no` | 系统生成 | `BX202610-00xx` 顺延 |
| `src` | 固定「问题上报转单」 | 与"商户端 / 物业巡逻"并列的来源 |
| `reporter` | WT.`by` | 原上报人 |
| `pl`（场所） | 抽屉选择，默认大唐袜业城 | 02 字典三场所 |
| `b` / `f`（楼栋 / 楼层） | 从 WT.`area` 拆分（如「A 栋 3F」→ A 栋 / 3F），可改 | 拆错可手工修正 |
| `unit`（档口位置） | WT.`unit`，可改 | 必填 |
| `type`（故障类型） | **抽屉选择**，默认按映射推荐 | 问题类型（消防/卫生/占道/设备/安全）与工单故障类型（照明/水电/门窗/地砖/空调/其他）**不同字典**，必须由人确认 |
| `desc` | WT.`desc`，可改 | ≥5 字 |
| `urg`（紧急程度） | 由 WT.`level` 映射（严重→紧急，其余→一般），可改 | |
| `photos` | WT.`photos` | 照片随单带入（水印保留） |
| `state` | 固定「待受理」 | 受理环节填派单人与预计到场 |
| `hours` / `doubt` / `expect` | 0 / false / 空 | 与新建一致，受理时填 `expect` |
| `createdAt` / `logs` | 当前时间 / 记录来源 WT 号 | 留痕「由问题上报 WTxxx 转入」 |

> 类型映射默认：卫生→水电；消防 / 占道 / 设备 / 安全→其他。**映射只是默认值，必须由操作人确认**——直接把"占道"写进工单故障类型会让维修工看不懂。

**规则**

| 编号 | 规则 |
|---|---|
| WT-1 | **转报修后原记录保留**（不删除、不改类型），仅回写 BX 号 |
| WT-2 | **不设改判**：责任方判断错误只影响归因统计与通知对象，可用"备注/留痕"说明，不产生单据联动 |
| WT-3 | **待处理超 3 天**列表标红「超 N 天」，每日提醒处置人 + 主管 |
| WT-4 | 提交处理结果必须同时有**说明 + 处理后照片**，否则不允许关闭 |
| WT-5 | 转报修后本页**只读**：工单状态在报修页推进，不回写 WT（避免两处状态打架） |
| WT-6 | **修正责任方 ≠ 改判**：只改归因标签，必须填原因并留痕；不改状态、不改单据、不触发通知重发（如需告诉商户，走线下沟通） |
