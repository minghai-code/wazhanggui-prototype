端：运营端 PC（yunying-PC）　｜　模块：07 物业服务（分册 §8.7） 页面：property-rectify.html　｜　页面版本：v1.0（2026-10-27） 前置：01-报修工单.md（含模块通用说明 §0）

1. 页面定位

把商户责任问题派给商户并跟踪到验收闭环。原「整改派发」「整改复核」两页合并为本页（4 个 Tab）。

  • 使用者：物业主管（派发 / 复核）
  • 上游：P6「派整改」、P8 投诉「转整改」
  • 下游：复核通过 → P6 关联问题转「已解决」

2. 分区结构

Tab内容
待派发问题已上报但未派发（可改限期、选通知方式）
整改中已派发，等商户提交（可催办、代录提交）
待复核商户已提交，等验收（可勾选批量通过）
已关闭已通过关闭 / 无效关闭

统计卡（4）：待派发 · 整改中 · 待复核 · 本月已关闭

列表（9 列，含勾选）：勾选（仅待复核）· 整改编号 ZG（带退回次数）· 关联问题 · 整改商户 · 整改要求 · 限期 · 状态 · 超期天数 · 操作

3. 状态机（4 态 + 2 终态）

stateDiagram-v2
    [*] --> 待派发: P6 派整改生成
    待派发 --> 整改中: 派发（选通知方式，限期不早于当日）
    整改中 --> 待复核: 商户提交（说明 + 照片）
    待复核 --> 已通过关闭: 复核通过 → 关联问题转「已解决」
    待复核 --> 整改中: 退回整改（原因必填，超期天数重置）
    整改中 --> 无效关闭: 现场复查无需整改

4. 整改单字段

字段必填说明
关联问题是自动带入（WT 号 + 描述 + 原照片）
整改商户是从 04 商户档案选，或按档口带出当前租户
整改要求是≥5 字（派发时以此为准，复核时逐条对照）
限期完成时间是不早于当日
通知方式是站内 / 短信 / 站内 + 短信（短信为独立服务，按条计费）

商户提交（端上，原型用「代录提交」演示）

字段必填校验
整改说明是≥5 字
整改后照片是≥1 张（无照片不能提交，ZG-3）
提交人自动—

5. 复核（本页关键）

抽屉必显前后照片并排对比：

┌────────────────┬────────────────┐
│  原问题照片     │  整改后照片     │
│  （红框，上报时）│  （绿框，提交时）│
└────────────────┴────────────────┘
操作效果
通过关闭整改单 → 已通过关闭，关联问题 → 已解决
退回整改原因必填（≥4 字），回 整改中，超期天数重置，退回次数 +1
批量通过勾选多张同批次通过，留痕（记录操作人与批次）

规则

编号规则
ZG-1超期未提交提醒商户 + 抄送主管
ZG-2退回累计 3 次自动升级主管（并抄送运营）
ZG-3无照片不能提交
ZG-4退回后超期天数重置（不累计，避免一次违约永久背锅）
