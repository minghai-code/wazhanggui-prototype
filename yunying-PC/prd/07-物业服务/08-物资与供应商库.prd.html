端：运营端 PC（yunying-PC）　｜　模块：07 物业服务（分册 §8.11） 页面：property-material.html　｜　页面版本：v1.1（2026-10-29） 前置：01-报修工单.md（含模块通用说明 §0）、02-交办单与核销.md

1. 页面定位

让交办单的物资行"有库可选"——把物业平时采购的物资、规格、单位、市场参考价与供应商提前维护成主数据，替代手工文本输入，从源头统一名称与单价口径。

  • 使用者：物业人员 / 物业主管（维护）、市场管理部（覆写参考价）、财务（只读）
  • 上游：预置基础库 / P3 历史采购导入归并 / P2 申报时新增
  • 下游：P2 物资行下拉 · P2 比价单与核销的供应商 · P3 类别与供应商维度 · P4 风控 R6
为什么做：此前物资行是自由文本，"地砖 600×600""600*600地砖""LED灯管"各写各的，导致比价失真、价格偏离无基准、供应商名录靠猜。该需求曾因"增加运营负担"被否，现录入交给物业公司（采购执行方，录一次用一年），运营只做启用/停用与价格覆写。

3. 「待合并」是什么

术语口径：对外一律用「待合并 / 合并重复」；"归一"是内部旧称，界面与文档均不再使用。
问题回答
它是什么物业申报时新建的物资，名称/规格疑似与库内已有物资是同一件东西（如「地砖 600*600」vs「防滑地砖 600×600」），等人工确认合并
怎么产生的建单时库中没有 → 当场新建入库 → 系统按名称/规格相似度给出疑似对象（字段 dupOf），条目标「待合并」
为什么不当场拦卡住提交会让物业改用「其他」绕过，库反而更乱。故当场放行、事后合并
怎么处理「待合并重复」筛出 → 行内「合并重复」→ 选保留哪条 → 确认；确认不是重复则「稍后处理」
合并后被合并的置停用 + 标「已合并」，新单下拉不再可选；采购次数与上次成交价并入保留项；历史单据不改写；写变更留痕
不处理会怎样只是提醒，不影响提交与核销（BD-11、BD-12）

页面必须做到：待合并行的名称下方直接写出疑似对象「疑似与 WL0001『防滑地砖 600×600』是同一物资」，并在工具栏提供「什么是待合并」帮助抽屉（讲清上面这张表）。

4. 建库三路

路径做法谁做产出
① 预置基础库系统按袜业城常见采购预置 18 条（地砖 / LED 灯管 / 空开 / 卷帘门导轨 / 给排水管件 / 消防器材 / 人工费…），带类别、规格、单位、参考价系统预置物业只需核对：改不合适的价、停用用不到的
② 历史采购导入P3「历史采购导入 / 建库」上传 Excel，按「名称 + 规格」归并生成物资、按名称归并生成供应商物业一次性（约半小时）存量全量进库，冷启动完成
③ 申报时顺手新增P2 建单时库中没有 → 点行末「+」填 5 个字段 → 当次即可用，同时入库并标「待合并」物业在申报时长尾物资持续沉淀，业务零阻断
不要求物业从零一条条录：①打底、②补存量、③补长尾，三条路合起来才叫"库建好了"。

7. 关键交互

交互行为
建单时选物资下拉可搜（名称 / 规格 / 编码）→ 自动带出规格、单位、参考价、默认供应商；规格只读（要换规格请选另一条或新建）
单价偏离录入单价与参考价差异 ≥20% 时行内提示"参考价 ¥x 偏高 y%"，不阻断（与 R-13 同口径）
库中没有行末「+」→ 抽屉只填 5 项（类别 / 名称 / 规格 / 单位 / 参考价）→ 保存即入库并回填本行（R-39）
待合并列表显示「疑似与 {疑似编码}『{疑似名称}』是同一物资」；点「合并重复」→ 选保留项 → 原条目置停用并标「已合并」，采购次数与上次成交价并入保留项，历史单据不改写
待补参考价参考价为空高亮；快捷筛选一键筛出，避免 R-13 长期失效
改价直接改、写留痕、不追溯已提交单据；运营覆写优先于物业录入（R-38）
停用二次确认；停用后新单不可选，历史交办单与核销记录完整保留
批量操作批量启用 / 停用 / 改类别，逐条写留痕
合并 / 删除删除一律不允许；合并只在「待合并」清单内进行
供应商集中预警供应商库「金额占比」列头带「?」，点击打开说明抽屉：占比怎么算 / 为什么要提醒（议价能力·断供风险·关联交易）/ 触发后做什么。占比 >70% 该行标「占比超 70%」。界面不出现「R6」字样，规则编号只留在 PRD 与风控看板内部

8. 业务规则

编号规则
BD-8申报时只能从库中选，不支持自由输入；库中没有就走「+ 新建」，口径必须落库
BD-9新增物资 / 供应商不设审批环节，直接生效；以「运营可覆写 + 留痕可查」替代审批
BD-10参考价 ≠ 成交价：参考价是人工维护的"市场价"，上次成交价是系统回写的"实付价"，两者并列展示供审批判断
BD-11库为空或某类别无条目不得阻断业务：待合并 与 待补参考价 是软提醒，不作为提交卡点
BD-12待合并不等于重复：确认不是同一物资时可不合并（点「稍后处理」），该条目按正常物资使用
