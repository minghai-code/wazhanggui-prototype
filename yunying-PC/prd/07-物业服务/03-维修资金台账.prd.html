1. 页面定位

一眼看清"今年 30 万花了多少、还剩多少、花在哪"，并管住超额申请。

  • 使用者：财务（核对）、物业主管（发起申请）、董事长（看额度红线）
  • 上游：P2 核销成功金额 → 计入「已核销」；P2 已通过未核销 → 计入「在途」
  • 下游：额度不足时阻断 P2 核销，引导到这里申请追加

6. 额外申请

6.1 申请字段

字段必填校验
申请金额是>0
用途说明是≥10 字
依据附件否报价单 / 说明文件
申请人 / 时间自动—

6.2 审批链（串行 2 级）

运营主管 → 财务

  • 运营主管通过 → 节点转「财务」，额度尚未追加
  • 财务通过 → 追加到当年总额度，留痕（申请人 / 审批人 / 金额 / 原因）
  • 驳回 → 原因必填（≥4 字），额度不追加
BD-3：额外申请通过后追加到当年总额度，跨期不结转。

7. 历史采购导入

项内容
模板列物资名称 / 规格 / 数量 / 单价 / 供应商 / 采购日期 / 发票号（可空）
校验物资名称与单价必填；单价 >0；日期格式 YYYY-MM-DD
失败处理整批回滚 + 失败行清单（每行标具体错误）
导入后写入历史成交价库（作为 P2 单价偏离校验的基准）
BD-5：历史采购导入不影响额度（历史年度已花掉），仅用于价格基准。

9. 验收要点
