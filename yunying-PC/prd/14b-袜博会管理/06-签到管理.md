## 1. 签到管理 `expo-checkin.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 现场入场核销（扫码）+ 手工补录 + 未到场标记 |
| 使用角色 | **现场核销**（专职）、运营主管 |
| 入口 | 菜单 → 文商旅管理 → 袜博会 → 签到管理 |
| 前置 | 观众登记已通过（有入场码） |
| 后置 | 核销记录归档；到场率更新；未核销标记未到场 |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | P3 已通过登记的入场码 |
| 本页操作的跨端影响 | 核销 → 观众端显示"已入场"；重复扫码 → 端上提示已核销时间 |
| 依赖的其他端页面 | 买家端入场码（含二维码） |
| 不涉及的端 | 商户端 |
| 一致性要求 | **核销幂等**；核销窗口 = 每日开馆前 1h 至闭馆 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「签到管理」+ 扫码入口 + 导出核销表 + 标记未到场 |
| **统计卡（4）** | 今日核销 / 累计核销 / 登记总数 / 到场率 |
| 筛选区 | 关键词 / 身份类型 / 参观日期 / 核销方式 + 查询 |
| 列表 | **10 列** + 分页 |
| 弹窗 | 手工补签（原因必填） |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 核销时间倒序，未核销在前 |
| 分页 | 页码 |
| 筛选组合 | 条件之间 **且** |
| 核销方式 | 扫码 / 手工补录 |
| 空结果 | **无空态提示**（待补） |

### 1.5 字段规格

| 列 | 字段 | 说明 |
|---|---|---|
| 入场编号 | `code` | `V+年+届次+4位` |
| 姓名 | `name` | — |
| 企业名称 | `company` | — |
| 身份类型 | `identity` | — |
| 参观日期 | `visitDate` | — |
| 登记时间 | `createdAt` | — |
| **核销时间** | `checkedAt` | 未核销为空 |
| 核销方式 | `way` | 扫码 / 手工补录 |
| 核销人 | `operator` | — |
| 操作 | — | 补签 / 撤销核销 |

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 扫码核销 | 展会期间 | 现场核销/主管 | 校验窗口 → 写入核销 | 重复 → E-34（⬜） |
| 手工补签 | 始终 | 现场核销/主管 | **原因必填** → 记"手工补录" | 缺原因 → 拦截 |
| 撤销核销 | 已核销 | 主管 | 回未核销 + 留痕 | 非主管 → 隐藏 |
| 标记未到场 | 展会结束后 | 主管 | 批量置未到场 | — |
| 导出核销表 | 始终 | 现场核销/主管 | Excel | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-28 | 核销窗口限制 | 扫码 | 开馆前 1h 至闭馆，窗外不可核销 | — |
| R-29 | **核销幂等** | 重复扫码 | 提示首次核销时间，不产生第二条（**⬜ 未实现**） | 端上 |
| R-30 | 手工补录必填原因 | 补签 | 记录 `way=手工补录` + 操作人 | — |
| R-31 | 到场率 = 已核销 ÷ 登记总数 | 渲染 | 实时 | 端上 |
| R-32 | 未到场由系统判定 | 展会结束 | 未核销 → 未到场 | — |
| R-33 | 撤销核销需主管 | 撤销 | 留痕 | — |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 数据 | 重复核销 | 拦截，提示首次核销时间（幂等） | 【已实现】「该观众已于 {时间} 核销，不可重复」 |
| 数据 | 非窗口期扫码 | 拦截 | 【待实现】应提示不在核销时段 |
| 数据 | 入场码无效 | 拦截 | 【待实现】应提示码无效 |
| 数据 | 手工补签缺原因 | 拦截 | 【待实现】 |
