## 1. 参观申请管理 `expo-visitor.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 审核观众参观登记，通过后生成**入场码**并短信下发 |
| 使用角色 | 文商旅运营专员、运营主管 |
| 入口 | 菜单 → 文商旅管理 → 袜博会 → 参观申请管理 |
| 前置 | 观众在买家端登记 |
| 后置 | 入场码可用于现场核销（P6）；资料下载解锁 |

> **与端上现状的差异**：买家端原型为"**提交即出证**"（无审核），本模块要求「**提交 = 待审核，通过后再发码**」。端上需改造（见 §0.6.1）。

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 买家端观众登记 |
| 本页操作的跨端影响 | 通过 → 端上收到入场码短信；驳回 → 端上显示驳回原因 |
| 依赖的其他端页面 | 买家端登记页 / 入场码 |
| 不涉及的端 | 商户端 |
| 一致性要求 | 入场编号 `V+年+届次+4位流水`；通过状态是资料解锁的前置 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「参观申请管理」+ 导出观众名单 + 批量通过 |
| **统计卡（5）** | 登记总数 / 待审核 / 已通过 / 已核销 / 到场率 |
| **Tab 条（3）** | 待审批 / 已通过 / 已驳回（各带数量角标） |
| 筛选区 | 关键词 / 身份类型 / 关注品类 / 参观日期 / 状态 + 查询 |
| 列表 | **10 列** + 分页 |
| 抽屉 | 登记详情（身份 / 企业 / 关注品类 / 审核记录） |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 登记时间倒序 |
| 分页 | 页码 |
| 筛选组合 | 条件之间 **且** |
| 状态 | 待审核 / 已通过 / 已驳回 / 已核销 / 未到场 / 已取消 |
| 到场率 | 已核销 ÷ 登记总数 |
| 空结果 | **无空态提示**（待补） |

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 通过 | 待审核 | 专员/主管 | 已通过 + 生成入场码 + **短信下发** | — |
| 驳回 | 待审核 | 专员/主管 | 必填原因 + 通知观众 | — |
| 批量通过 | 有勾选 | 专员/主管 | 逐条生成码并发送 | — |
| 导出名单 | 始终 | 专员/主管 | Excel（手机号脱敏） | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-14 | 通过才生成入场码 | 审核 | 码规则 `V+年+届次+4位流水` | 端上 |
| R-15 | 码唯一且与手机号绑定 | 生成 | 一人一码 | — |
| R-16 | 通过是资料解锁前置 | 下载 | 仅已通过可下载受限资料 | 端上 |
| R-17 | 短信失败可重发 | 发送 | 记录失败原因 | — |
| R-18 | 未到场由系统判定 | 展会结束 | 未核销 → 未到场 | — |

### 1.10 验收标准

| 编号 | 前置 | 操作 | 预期 | 级别 |
|---|---|---|---|---|
| AC-13 | 待审核登记 | 点通过 | 状态已通过，生成入场码并短信下发 | P0 |
| AC-14 | 同上 | 查看入场编号 | 形如 `V26-18-0001` | P0 |

| AC-16 | 已通过观众 | 端上下载受限资料 | 允许下载 | P1 |
| AC-17 | 展会结束仍未核销 | 系统扫描 | 置「未到场」 | P1 |
