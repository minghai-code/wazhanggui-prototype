1. 合同发起与签署 contract-apply.html

1.1 页面说明

项内容
页面目标从竞拍结果主动发起合同 → 短信通知 → 商户手写签名 → 专员审核签字 → 盖章归档
使用角色合同管理专员（全流程一条龙）
入口菜单 → 合同管理 → 合同发起与签署；也从 P2 台账「签署」按钮进入
前置浙交会竞拍结果已录入（手工或批量导入）
后置生效 → 02 在租 + 04 建档 + 06 应收计划
v1.4 关键口径：合同由合同专员主动发起（不是商户申请）；「生成并发送」是同一动作，完成后直接进入「待商户签字」。

1.2 本页端间关系

项内容
本页数据来源竞拍结果（浙交会，人工录入 / 批量导入）
本页操作的跨端影响发送 → 商户收到短信 → 同号注册后「合同管理」出现待签合同 → 手写签名后回流待审核
依赖的其他端页面shanghu-APP/contract.html（待签合同 + 手写签名入口缺，需新增）
不涉及的端买家端（只做账号注册，不承载签署）
一致性要求手机号 = 签署匹配键，须与竞拍登记一致；不一致 → 专员改绑

1.3 页面结构

区块内容
顶部标题「合同发起与签署」+ 导出台账 + 同步商户端
统计卡待发起合同（竞拍结果）/ 待商户签字 / 待签署审核 / 短信已送达（累计）/ 盖章件待回传
Tab1 竞拍结果与发起竞拍结果表（8 列）+ 新建 / 批量导入
Tab2 签署与盖章签署单表（9 列）+ 6 个操作
Tab3 短信发送记录短信记录表（7 列）+ 重发

1.4 列表、筛选与排序

Tab筛选排序
Tab1关键词 / 资源类型 / 发起状态录入时间倒序
Tab2关键词 / 签署状态 / 处理人 / 仅超时停留时长降序
Tab3合同号 / 手机号 / 发送结果发送时间倒序

空结果分别提示「暂无竞拍结果」「暂无签署单」「暂无短信记录」。

1.5 字段规格

Tab1 竞拍结果（8 列）：资源/类型 · 承租方（主体/联系人/电话）· 租期/年租金 · 成交价 · 企业类型 · 录入来源 · 发起状态 · 操作

Tab2 签署单（9 列）：合同号 · 承租人/资源 · 租期 · 年租金 · 签署状态 · 处理人 · 短信 · 停留时长 · 操作

Tab3 短信记录（7 列）：合同号 · 接收手机号 · 短信内容（模板占位）· 发送时间 · 重试 · 结果 · 操作

签署状态（5 态）：待发起 → 待商户签字 → 待签署审核 → 已存档·生效中 / 已撤回（盖章件：待回传 / 已回传）

1.6 交互规则

元素所在 Tab可点条件点击后禁止表现

审核签字2待签署审核核对签名 → 通过 = 合同生效—

1.7 业务规则与计算口径

编号规则触发处理影响端
R-21生成 + 发送是同一动作发起无独立「待生成」态商户端
R-22短信失败重试 3 次发送仍失败提醒专员—
R-23手机号 = 签署匹配键发起/改绑必须与竞拍登记一致商户端
R-24撤回 → 退回待发起撤回合同号不变，v+1，留痕「已撤回·待重新发起」—
R-25审核通过即生效审核触发 02/04/06三处
R-26盖章件只影响归档上传不影响生效状态—
R-27停留时长超阈提醒定时待商户签字超 N 天提醒专员—

1.8 异常与边界

类型场景系统行为提示文案
数据竞拍结果缺必填拦截【已实现】「资源编号与承租方名称为必填项」
数据手机号非 11 位拦截【已实现】「手机号格式不正确（应为 11 位数字，与竞拍登记一致）」
数据改绑手机号格式错拦截【已实现】「手机号格式不正确（11 位数字）」
数据撤回未填原因拦截【已实现】「撤回原因必填（用于留痕与追溯）」
依赖商户未注册待签合同不可达（端上提示后由专员改绑手机号）—
