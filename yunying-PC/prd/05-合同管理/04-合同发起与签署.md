## 1. 合同发起与签署 `contract-apply.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 从竞拍结果**主动发起**合同 → 短信通知 → 商户手写签名 → 专员审核签字 → **上传盖章扫描件 → 合同生效归档** |
| 使用角色 | 合同管理专员（全流程一条龙） |
| 入口 | 菜单 → 合同管理 → 合同发起与签署；也从 P2 台账「签署」按钮进入 |
| 前置 | 浙交会竞拍结果已录入（手工或批量导入） |
| 后置 | **盖章件回传 → 合同生效** → 02 在租 + 04 建档 + 应收计划 |

> **v1.4 关键口径**：合同由**合同专员主动发起**（**不是商户申请**）；「生成并发送」是**同一动作**，完成后直接进入「待商户签字」。

> **状态机（v1.11 · 2026-10-26 订正）**
> `待发起 → 待商户签字 → 待签署审核 →` **`待盖章归档`** `→ 已存档·生效中`
>
> **生效点 = 盖章件回传**（不再以"审核通过"为生效点）：
> - **审核签字通过** → 转「**待盖章归档**」：只代表"内容与签名无误"，**合同尚未生效**，**不推送** 02 / 04 / 应收；
> - **上传线下盖章扫描件** → 转「已存档·生效中」：**此时才生效**，并推送 02（档口在租）/ 04（自动建档 + 物业权限）/ 应收计划；
> - 未回传期间**不计为生效合同**；超 **15 天**未回传升级提醒主管。
>
> 客户口径（2026-10-26）：商户签完字、运营审核完，**还要上传线下盖完章的扫描件才算真正结束**。

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 竞拍结果（浙交会，人工录入 / 批量导入） |
| 本页操作的跨端影响 | 发送 → 商户收到短信 → **同号注册**后「合同管理」出现待签合同 → 手写签名后回流待审核 |
| 依赖的其他端页面 | `shanghu-APP/contract.html`（**待签合同 + 手写签名入口缺，需新增**） |
| 不涉及的端 | 买家端（只做账号注册，**不承载签署**） |
| 一致性要求 | 手机号 = 签署匹配键，须与竞拍登记一致；不一致 → 专员改绑 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「合同发起与签署」+ 导出台账 + 同步商户端 |
| **统计卡** | 待发起合同（竞拍结果）/ 待商户签字 / 待签署审核 / **待盖章归档** / **已归档·生效中** |
| **Tab1 竞拍结果与发起** | 竞拍结果表（**8 列**）+ 新建 / 批量导入 |
| **Tab2 签署与盖章** | 签署单表（**9 列**）+ 6 个操作 |

### 1.4 列表、筛选与排序

| Tab | 筛选 | 排序 |
|---|---|---|
| Tab1 | 关键词 / 资源类型 / 发起状态 | 录入时间倒序 |
| Tab2 | 关键词 / 签署状态 / 处理人 / **仅超时** | 停留时长降序 |
| Tab3 | 合同号 / 手机号 / 发送结果 | 发送时间倒序 |

空结果分别提示「暂无竞拍结果」「暂无签署单」「暂无短信记录」。

### 1.5 字段规格

**Tab1 竞拍结果（8 列）**：资源/类型 · 承租方（主体/联系人/电话）· 租期/年租金 · 成交价 · 企业类型 · 录入来源 · 发起状态 · 操作

**Tab2 签署单（9 列）**：合同号 · 承租人/资源 · 租期 · 年租金 · 签署状态 · 处理人 · 短信 · **停留时长** · 操作

**Tab3 短信记录（7 列）**：合同号 · 接收手机号 · 短信内容（模板占位）· 发送时间 · 重试 · 结果 · 操作

**签署状态（5 态）**：待发起 → 待商户签字 → 待签署审核 → 已存档·生效中 / 已撤回（盖章件：待回传 / 已回传）

### 1.6 交互规则

| 元素 | 所在 Tab | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| 新建竞拍结果 | 1 | 专员 | 弹窗（资源编号 / 承租方 / 主体类型 / 电话） | 缺必填 → K-35 |
| 批量导入 | 1 | 专员 | 上传 → 校验 → 全部通过才入库 | 有错 → 失败清单 |
| **重新发起并发送** | 1 | 状态=待发起 | 选模板 + 变量填充 + 编辑 → 生成并发送（同一动作） | 手机号不符 → K-36 |
| 重发短信 | 2/3 | 待商户签字 | 只催办，内容与版本不变 | — |
| **改绑手机号** | 2 | 待商户签字 | 校验 11 位 → 改绑 + 重发 | 格式错 → K-41 |
| **撤回** | 2 | 待商户签字 | 原因必填 → 退回「待发起」，v+1、合同号不变 | 空原因 → K-43 |
| 审核签字 | 2 | 待签署审核 | 核对签名 → 通过 = 转「**待盖章归档**」（**尚未生效**） | — |
| **上传盖章件** | 2 | **待盖章归档** | 上传线下盖章扫描件 → **合同生效并归档**，推送 02 / 04 / 应收 | 未回传不生效 |
| 查看来源 | 3 | 有合同号 | 跳 Tab2 定位签署单 | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-21 | 生成 + 发送是同一动作 | 发起 | 无独立「待生成」态 | 商户端 |
| R-22 | 短信失败重试 3 次 | 发送 | 仍失败提醒专员 | — |
| R-23 | 手机号 = 签署匹配键 | 发起/改绑 | 必须与竞拍登记一致 | 商户端 |
| R-24 | 撤回 → 退回待发起 | 撤回 | **合同号不变**，v+1，留痕「已撤回·待重新发起」 | — |
| R-25 | 审核通过即生效 | 审核 | 触发 02/04/06 | 三处 |
| R-26 | 盖章件只影响归档 | 上传 | 不影响生效状态 | — |
| R-27 | 停留时长超阈提醒 | 定时 | 待商户签字超 N 天提醒专员 | — |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |

| 依赖 | 商户未注册 | 待签合同不可达（端上提示后由专员改绑手机号） | — |

### 1.9 通知与消息

| 事件 | 接收人 | 渠道 | 抑制条件 |
|---|---|---|---|
| 合同生成并发送 | 竞拍人（按竞拍登记手机号） | **短信**（模板可配） | 失败重试 3 次 |
