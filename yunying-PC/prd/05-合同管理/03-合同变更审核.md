## 1. 合同变更审核 `contract-change.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 合同专员**发起变更** → 商户端**重签变更协议** → 回到本页**审核签署** → 新版本生效 |
| 使用角色 | **合同管理专员**（发起 / 催签 / 撤回 / 审核商户签署 / 通过）；**无主管审批环节**（2026-11-04 业务确认：新签与变更均由专员一人闭环） |
| 入口 | 菜单 → 合同管理 → 合同变更审核 |
| 前置 | 原合同处于「已存档 · 生效中」；发起后系统生成 v+1 变更协议并短信通知商户 |
| 后置 | **以商户签署版本为准**：合同号不变、生成 v+1 生效、旧版本只留查；重推 02 / 06 / 04 |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | **合同专员发起**（主口径；商户端申请作为补充来源） |
| 本页操作的跨端影响 | 发起 → 商户端「我的合同 → 待签署」出现**变更协议 v+1** + 短信；通过 → 04 档案同步 + 签署匹配键同步 + 重推 02/06；驳回 → 商户端可见原因 |
| 依赖的其他端页面 | `shanghu-APP/contract.html`（待签署 Tab 已含「变更补充协议」）、`contract-detail.html`（版本留痕） |
| 不涉及的端 | 买家端 |
| 一致性要求 | 合同号不变；**没有商户签名不得通过**（待签署 → 待审核 → 已通过）；通过后以签署版本为准 |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题「合同变更审核」+ **发起变更（跳转变更办理页）** + 导出 |
| 发起入口（v1.15） | 「发起变更」→ 回 **合同台账** 并自动弹出**变更办理弹层**（带当前合同号）：以整份合同为主体改字段、可同时改多处，提交后生成一条「待签署」变更单（见 `05-合同变更办理.md`）；**不再有独立的「合同变更办理」菜单项** |
| 从台账跳入提示 | `?no=` 带合同号时，顶部显示「已按合同号过滤」+ 重置 |
| **统计卡（4）** | 待商户签署 / 待审核（商户已签）/ 本月通过 / 本月驳回·撤回 |
| 筛选区 | 关键词 + 变更类型 + 来源 + 状态 + 日期 + 查询 + 重置 |
| 列表 | **8 列** + 分页（状态列附签署进度） |
| 审批抽屉 | **① 变更单信息 → ② 合同基本信息（整份合同，对齐台账 21 字段，v1.13）→ ③ 变更前后对比（支持多条差异）→ ④ 商户重签记录（含签名图）→ ⑤ 下游影响预览** + 按状态分派的按钮 |

### 1.4 列表、筛选与排序

| 项目 | 规则 |
|---|---|
| 默认排序 | 提交时间倒序 |
| 分页 | 页码 |
| 筛选组合 | 条件之间 **且** |
| 变更类型（**六类**） | 租金 / 租期 / 面积 / 承租人 / **主体信息变更** / 摊位号（拆"终止 + 新签"） |
| 状态 | **待签署 / 待审核 / 已通过 / 已驳回 / 已撤回** |
| 空结果 | 「暂无变更单」 |

### 1.5 字段规格

**变更列表（8 列）**

| 列 | 字段 | 说明 |
|---|---|---|
| 变更单号 | `id` | — |
| 合同号 / 承租人 | `contractNo` / `tenant` | **企业主体显示企业名称 + 联系人** |
| 变更类型 | `type` | 六类；**重大标记**（租金/租期/面积/承租人/主体信息 = 审核签署前需核验材料；**不涉及主管审批**） |
| 变更前后对比 | `diff` | 摘要，含**主体信息组** |
| 来源 / 提交人 | `source` / `submitter` | 商户端申请 / 专员发起 |
| 提交时间 | `submitAt` | — |
| 状态 | `state` | 待签署 / 待审核 / 已通过 / 已驳回 / 已撤回（附等待天数 · 签署时间 · 驳回原因） |
| 操作 | — | 待签署：**催签 / 撤回 / 详情**；待审核：**审核 / 详情**；**已驳回：修改后重新送签 / 详情**；**已通过：上传/查看变更盖章件 / 详情**；已撤回：详情 |

**前后对比（3 列）**：字段 / 改前 / 改后
> 主体信息组包含：主体类型切换 / 企业名称 / 统一社会信用代码 / 法定代表人·联系人 / 联系电话 / 企业类型。

### 1.6 交互规则

| 元素 | 显示条件 | 可点条件 | 点击后 | 禁止表现 |
|---|---|---|---|---|
| **发起变更** | 始终 | 专员 | 抽屉填写 → 提交：需重签类 → 生成 v+1 变更协议 + 短信 + 状态「待签署」；免重签类 → 直接「待审核」 | 缺变更后值 / 缺原因 → 拦截 |
| 审核 | 状态=待审核 | 专员 | 抽屉（对比 + **商户签名图** + 签署记录 + 下游影响预览） | 待签署状态无「通过」按钮 |
| **催签** | 状态=待签署 | 专员 | 重发签署短信 + 记录催签时间 | — |
| **撤回** | 状态=待签署 | 专员 | 二次确认 → 变更单「已撤回」，商户端待签任务取消 | 已签后不可撤回（走驳回） |
| 通过（需重签类） | 状态=待审核 | 专员 | **以签署版本为准**回写 + 重推 02/06/04 | 无签署记录 → 拦截 |
| 主体信息变更 | 类型=主体 | **合同专员** | **必须先勾「主体变更核验」** | 未勾 → K-29 |
| 驳回 | 待审核 | **合同专员** | 必须填原因 | 空 → K-31 |
| **修改后重新送签** | 状态=已驳回 | 合同专员 | 跳办理页（`?no=&bg=单号`）**带出上次修改值**；提交后同单号回「待签署」，送签次数 +1 | 不新建变更单 |
| **上传变更盖章件** | 状态=已通过 | 合同专员 | 弹层上传 PDF/JPG；上传后改「查看盖章件」 | 未上传在列表标「盖章件未上传（需补）」 |
| 详情 | 始终 | 始终 | 只读 | — |

### 1.7 业务规则与计算口径

| 编号 | 规则 | 触发 | 处理 | 影响端 |
|---|---|---|---|---|
| R-14 | 合同号不变，生成新版本 | 通过 | 保留历史版本 | — |
| R-15 | **签署链路无主管审批**（2026-11-04 业务确认） | 新签 + 变更 | 合同专员一人闭环：发起 / 审核商户签署 / 通过；重大变更仅需专员核验材料，不设主管节点 | — |
| R-16 | 主体变更核验 | 主体信息类 | 信用代码 18 位且不重复 + 已收工商变更证明 | 04 |
| R-17 | 电话变更同步签署键 | 联系电话变更 | 04 档案同步；在签署中 → 改绑重签 | 04、商户端 |
| R-18 | 需重签补充协议 | 租金/租期/主体类 | 打「需重签变更补充协议」标记 | 商户端 |
| R-19 | 摊位号变更 = 终止 + 新签 | 该类型 | 不直接改，拆两步 | 02 |
| R-20 | 通过后重推 02/06/04 | 通过 | 档口/应收/档案同步更新 | 三处 |
| R-21 | **重签在前、审核在后** | 需重签类变更 | 发起即「待签署」；商户签署后才进「待审核」；无签署记录**禁止通过** | 商户端 |
| R-22 | **以签署版本为准** | 通过 | 以商户签署的 v+1 作为生效版本，旧版本标记「历史版本，仅供查阅」 | 三处 |
| R-23 | **重签判定细化到字段** | 主体信息变更 | 主体类型 / 承租方名称 / 统一社会信用代码 / **证件号（v1.17，补录身份证号即改正文主体栏）** 变动 = 需重签；仅联系人 / 联系电话 = 不需重签（通过即生效 + 同步签署手机号） | 商户端 |
| R-24 | **撤回仅限待签署** | 待签署 | 撤回 → 「已撤回」+ 商户端待签任务取消；已签后只能驳回 | 商户端 |
| R-25 | **驳回同单号重送** | 已驳回 | 驳回原因多为「商户签名不合格」→ 修正后同单号重新送签，**不要求专员重新发起、不新建单号** | 商户端 |
| R-26 | **盖章件在审核通过后上传** | 已通过 | 变更协议签署并审核通过 → 下载变更后合同 → 双方盖章 → 回传扫描件；未上传标「需补」 | 台账归档 |

### 1.8 异常与边界

| 类型 | 场景 | 系统行为 | 提示文案 |
|---|---|---|---|
| 数据 | 主体变更未核验 | 拦截 | 【已实现】「主体信息变更：请先勾选「主体变更核验」…」 |
| 数据 | 驳回未填原因 | 拦截 | 【已实现】「驳回原因必填」 |
| 数据 | 信用代码与他企重复 | 拦截 | 【待实现】应提示重复企业 |
| 权限 | 非合同专员账号 | 变更页只读（无发起 / 审核 / 催签 / 撤回按钮） | 无权限，请联系管理员 |
