v1.17 关键口径（2026-11-10，依据客户线下样本合同 ziliao/拍卖一楼摊位租赁合同（样本）.docx） 样本合同抬头为 承租方（乙方）：________ 社会信用代码（身份证号码）：________ —— 个人填身份证号、企业填统一社会信用代码，共用同一栏位，正文没有"可留空"的含义。因此本页把证件号与联系电话定为发起（生成并发送）前必填： - 证件号：个人 = 身份证号（18 位）；企业 = 统一社会信用代码（必填）+ 法定代表人 / 经办人身份证号； - 联系电话：签署匹配键（商户账号与待签合同靠它匹配），且必须渲染进合同正文（样本正文无此栏，但线上签署必须有）； - 缺失一律拦截发送（K-51 / K-52），不得生成"主体栏空白"的合同； - 录入竞拍结果阶段可留空（存量数据补录场景），但状态提示「身份待补全」，发起前必须补齐。
状态机（v1.11 · 2026-10-26 订正） 待发起 → 待商户签字 → 待签署审核 → 待盖章归档 → 已存档·生效中 生效点 = 盖章件回传（不再以"审核通过"为生效点）： - 审核签字通过 → 转「待盖章归档」：只代表"内容与签名无误"，合同尚未生效，不推送 02 / 04 / 应收； - 上传线下盖章扫描件 → 转「已存档·生效中」：此时才生效，并推送 02（档口在租）/ 04（自动建档 + 物业权限）/ 应收计划； - 未回传期间不计为生效合同；超 15 天未回传升级提醒主管。 客户口径（2026-10-26）：商户签完字、运营审核完，还要上传线下盖完章的扫描件才算真正结束。

1.5 字段规格

Tab1 竞拍结果（8 列）：资源/类型 · 承租方（主体/联系人/电话）· 租期/年租金 · 成交价 · 企业类型 · 录入来源 · 发起状态 · 操作

Tab2 签署单（9 列）：合同号 · 承租人/资源 · 租期 · 年租金 · 签署状态 · 处理人 · 短信 · 停留时长 · 操作

Tab3 短信记录（7 列）：合同号 · 接收手机号 · 短信内容（模板占位）· 发送时间 · 重试 · 结果 · 操作

发起抽屉（生成合同并发送）字段（v1.17）：合同模板 *（按资源类型带出）· 签署人手机号 *（只读，取竞拍登记）· 承租人 · 资源 / 档口编号 · 租期 · 年租金 · 证件号 \*（新增；个人 = 身份证号，企业 = 法定代表人 / 经办人身份证号，18 位，末位可为 X）· 统一社会信用代码（只读）· 法定代表人 / 联系人（只读）· 企业类型 · 合同正文（可编辑，抬头为「承租方 + 社会信用代码（身份证号码）」同一行 + 「联系人 / 联系电话」一行）

  • 证件号输入框默认取竞拍结果录入值；录入时为空（显示「身份待补全」）→ 发起时必须填，否则 K-51；
  • 正文渲染兜底：证件号或联系电话缺失时，正文对应位置渲染 ＿＿＿（待补·不可发送），且不允许点发送。

签署状态（5 态）：待发起 → 待商户签字 → 待签署审核 → 已存档·生效中 / 已撤回（盖章件：待回传 / 已回传）
