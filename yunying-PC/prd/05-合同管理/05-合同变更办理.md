## 1. 合同变更办理 `contract-change-create.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 让合同专员**对着整份合同**决定"改哪里"，一次改多处，提交后生成**一条**变更单（多条字段差异） |
| 使用角色 | 合同管理专员（**无主管审批**） |
| 入口 | **只有台账入口**：① 合同台账行内点「变更」→ **台账内右侧弹层**（不再跳页、**不占菜单**）② 变更审核页「发起变更」→ 回台账并自动弹层；③ 已驳回单「修改后重新送签」→ 回台账弹层并带 `bg=单号` |
| 形态 | 弹层宽 `min(1180px,96vw)`，内嵌本页（`?embed=1`，隐藏页头，只留表单）；提交后通过 `postMessage` 通知台账**关闭弹层 + 刷新列表**，不再跳页 |
| 前置 | 合同处于「生效中 / 变更中」；原合同已存档 |
| 后置 | 需重签类 → 变更单「待签署」+ 短信通知商户；一般项（仅联系人/电话）→「待审核」 |

### 1.2 端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 合同台账（21 字段）；台账 → 本页通过 `?no=` 带入合同号 |
| 本页操作的跨端影响 | 提交 → 商户端「我的合同 → 待签署」出现**变更协议 v+1**（含多处变更对比）；同时生成变更单供审核 |
| 依赖的其他端页面 | `shanghu-APP/contract.html`（待签署 Tab） |
| 一致性要求 | 一条变更单 = 一次签署 = 一个版本；**不允许把一次多处修改拆成多次发起** |

### 1.3 页面结构

| 区块 | 内容 |
|---|---|
| 顶部 | 标题 + 合同版本标记（v1 → v2）+ 返回台账 / 去变更审核 |
| 当前合同 | 合同下拉（从台账带入时默认选中）+ 合同摘要（承租方 / 档口 / 面积 / 租期 / 年租金 / 状态） |
| **① 合同基本信息** | 对齐线下《出租合同台账》**21 字段**；**可改字段用橙色底**，其余只读 |
| **② 本次变更摘要** | 实时 diff（改前 → 改后）+ 自动变更类型标签 + 「共 N 处修改 → 只生成 1 条变更单」 |
| **③ 变更原因** | 变更原因（必填，商户可见）；**本环节不上传附件** —— 盖章件在审核通过后再上传（见 `03-合同变更审核.md`） |
| 驳回修正模式 | 带 `?bg={变更单号}` 进入：标题显示「驳回修正 · 同单号重新送签」，红条展示驳回原因，字段**预填上次修改值**，提交按钮变「修正后重新送签」，**单号复用不新建** |
| 底部 | 取消 / 提交变更并送签 |

### 1.4 可修改字段（仅这些可改，其余只读）

| 字段 | key | 归属变更类型 | 是否需重签 |
|---|---|---|---|
| 年租金（元） | `rent` | 租金变更 | 是 |
| 租赁起始日 / 终止日 | `start` / `end` | 租期变更 | 是 |
| 出租面积（㎡） | `area` | 面积变更 | 是 |
| 承租方（乙方） | `name` | 承租人变更 | 是 |
| 主体类型 | `ptype` | 主体信息变更 | 是 |
| 统一社会信用代码 | `uscc` | 主体信息变更 | 是 |
| 法定代表人 / 联系人 | `contact` | 主体信息变更 | **否**（一般项） |
| 联系电话（签署匹配键） | `phone` | 主体信息变更 | **否**（一般项） |

> 档口 / 摊位号变更**不在本页**：按规则拆「终止 + 新签」。
> 保证金、租金收取方式、出租依据、不动产权证号、合同状态、版本 → **只读**。

### 1.5 字段规格（只读部分）

合同号 · 卷号 · 资产类型（商铺）· 资产名称（摊位号）· 坐落地址 · 不动产权证号 · 主体类型 · 承租方 · 统一社会信用代码 · 法定代表人/联系人 · 联系电话 · 出租面积 · 租赁起止 · 年租金 · 履约保证金（固定，不可改）· 租金收取方式 · 出租依据 · 合同状态 · 当前版本

### 1.6 交互规则

| 元素 | 条件 | 结果 |
|---|---|---|
| 修改任一橙色字段 | — | ② 区实时刷新 diff 与变更类型；无修改时不显示 |
| 提交 | 至少 1 处修改 + 原因必填 | 生成 1 条变更单；需重签 → 「待签署」（发短信）；免重签 → 「待审核」；90 秒后跳回变更审核页并按合同号过滤 |
| 提交（无修改） | — | 拦截：「请至少修改一处需要变更的字段（橙色底输入框）」 |
| 提交（无原因） | — | 拦截：「变更原因必填（商户端会看到）」 |
| 切换合同 | — | 重新加载字段，清空原因（避免串味） |
| 取消 | — | 返回台账，不保存 |

### 1.7 业务规则

| 编号 | 规则 |
|---|---|
| CC-1 | **一条变更单承载多条字段差异**，不得让专员为"改租金 + 改租期"发起两次 |
| CC-2 | 变更类型由**修改的字段自动推导**，可叠加（如「租金变更 + 租期变更」） |
| CC-3 | 需重签判定：租金/租期/面积/承租方/主体重大项 → 重签；仅联系人/电话 → 免重签 |
| CC-4 | 合同号不变，提交后为 v+1；提交仅生成**待签协议**，不立即改台账数值 |
| CC-5 | 提交后原合同状态置「变更中」，买家/商户侧展示「变更中 · 待签署」 |
| CC-6 | 待签署阶段专员可「催签 / 撤回」；撤回后商户端待签任务消失，变更单「已撤回」 |
| CC-7 | 一个合同同一时间只允许一条**在途**变更单（待签署/待审核）；已有在途单 → 拦截并提示先去处理 |
| CC-8 | **驳回后同单号重新送签**：专员驳回多为「商户签名不合格」→ 从审核页「修改后重新送签」回到本页，**带出上次修改值**，提交后**同一个变更单号**回「待签署」（记录送签次数），不新建单、不用重新填一遍 |
| CC-9 | **发起时不传附件**：盖章件在**审核通过后**于变更审核列表上传（变更后合同下载 → 双方盖章 → 回传扫描件）；工商变更证明等材料在审核时线下核验 |

### 1.8 异常与边界

| 场景 | 处理 |
|---|---|
| 合同已有在途变更单 | 拦截，提示：「该合同已有在途变更单（BG20xx），请先完成审核或撤回」 |
| 合同已终止 / 已作废 | 不允许发起（入口不可用） |
| 主体类型由个人→企业 | 必须同时填企业名称 + 统一社会信用代码 + 联系人 + 电话，否则拦截 |
| 面积改小但已缴租金不退 | 提示「面积调整不影响已缴租金，差额在下一租赁年度抵扣」 |

### 1.9 验收标准

| # | 前置 | 操作 | 预期 | 优先级 |
|---|---|---|---|---|
| AC-CC1 | 台账任一合同 | 点「变更」 | **在本页弹出变更办理层**并带入该合同，字段全部载入（不跳转、不出现独立菜单） | P0 |
| AC-CC9 | 弹层内提交 | 提交变更 | 弹层自动关闭、台账列表刷新、提示变更单号与状态 | P0 |
| AC-CC2 | 办理页 | 同时改年租金 + 租期 | ② 区显示 2 处 diff + 2 个类型标签；提交只生成 **1 条**变更单 | P0 |
| AC-CC3 | 办理页 | 仅改联系电话 | 提交后变更单直接「待审核」（免重签） | P0 |
| AC-CC4 | 办理页 | 未改任何字段就提交 | 拦截 | P1 |
| AC-CC5 | 提交后 | 变更审核页 | 列表出现该变更单，状态「待签署」，含多条字段差异 | P0 |
| AC-CC6 | 已有在途变更单的合同 | 再次发起 | 拦截并提示先处理在途单 | P1 |
| AC-CC7 | 已驳回的变更单 | 点「修改后重新送签」 | 打开办理页并预填上次修改值；提交后**同单号**回「待签署」，送签次数 +1 | P0 |
| AC-CC8 | 新发起变更 | 查看办理页 | **无附件上传项**，提示盖章件在审核通过后上传 | P1 |
