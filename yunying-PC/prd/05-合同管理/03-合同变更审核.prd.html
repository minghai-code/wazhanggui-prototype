1.1 页面说明

项内容
页面目标合同专员发起变更 → 商户端重签变更协议 → 回到本页审核签署 → 新版本生效
使用角色合同管理专员（发起 / 催签 / 撤回 / 审核商户签署 / 通过）；无主管审批环节（2026-11-04 业务确认：新签与变更均由专员一人闭环）
入口菜单 → 合同管理 → 合同变更审核
前置原合同处于「已存档 · 生效中」；发起后系统生成 v+1 变更协议并短信通知商户
后置以商户签署版本为准：合同号不变、生成 v+1 生效、旧版本只留查；重推 02 / 06 / 04

1.2 本页端间关系

项内容
本页数据来源合同专员发起（主口径；商户端申请作为补充来源）
本页操作的跨端影响发起 → 商户端「我的合同 → 待签署」出现变更协议 v+1 + 短信；通过 → 04 档案同步 + 签署匹配键同步 + 重推 02/06；驳回 → 商户端可见原因
依赖的其他端页面shanghu-APP/contract.html（待签署 Tab 已含「变更补充协议」）、contract-detail.html（版本留痕）
不涉及的端买家端
一致性要求合同号不变；没有商户签名不得通过（待签署 → 待审核 → 已通过）；通过后以签署版本为准

1.6 交互规则

元素显示条件可点条件点击后禁止表现
发起变更始终专员抽屉填写 → 提交：需重签类 → 生成 v+1 变更协议 + 短信 + 状态「待签署」；免重签类 → 直接「待审核」缺变更后值 / 缺原因 → 拦截
审核状态=待审核专员抽屉（对比 + 商户签名图 + 签署记录 + 下游影响预览）待签署状态无「通过」按钮
催签状态=待签署专员重发签署短信 + 记录催签时间—
撤回状态=待签署专员二次确认 → 变更单「已撤回」，商户端待签任务取消已签后不可撤回（走驳回）
通过（需重签类）状态=待审核专员以签署版本为准回写 + 重推 02/06/04无签署记录 → 拦截
主体信息变更类型=主体合同专员必须先勾「主体变更核验」未勾 → K-29
驳回待审核合同专员必须填原因空 → K-31
修改后重新送签状态=已驳回合同专员跳办理页（?no=&bg=单号）带出上次修改值；提交后同单号回「待签署」，送签次数 +1不新建变更单
上传变更盖章件状态=已通过合同专员弹层上传 PDF/JPG；上传后改「查看盖章件」未上传在列表标「盖章件未上传（需补）」
详情始终始终只读—
