1. 合同变更办理 contract-change-create.html

1.1 页面说明

项内容
页面目标让合同专员对着整份合同决定"改哪里"，一次改多处，提交后生成一条变更单（多条字段差异）
使用角色合同管理专员（无主管审批）
入口只有台账入口：① 合同台账行内点「变更」→ 台账内右侧弹层（不再跳页、不占菜单）② 变更审核页「发起变更」→ 回台账并自动弹层；③ 已驳回单「修改后重新送签」→ 回台账弹层并带 bg=单号
形态弹层宽 min(1180px,96vw)，内嵌本页（?embed=1，隐藏页头，只留表单）；提交后通过 postMessage 通知台账关闭弹层 + 刷新列表，不再跳页
前置合同处于「生效中 / 变更中」；原合同已存档
后置需重签类 → 变更单「待签署」+ 短信通知商户；一般项（仅联系人/电话）→「待审核」

1.2 端间关系

项内容
本页数据来源合同台账（21 字段）；台账 → 本页通过 ?no= 带入合同号
本页操作的跨端影响提交 → 商户端「我的合同 → 待签署」出现变更协议 v+1（含多处变更对比）；同时生成变更单供审核
依赖的其他端页面shanghu-APP/contract.html（待签署 Tab）
一致性要求一条变更单 = 一次签署 = 一个版本；不允许把一次多处修改拆成多次发起

1.3 页面结构

区块内容
顶部标题 + 合同版本标记（v1 → v2）+ 返回台账 / 去变更审核
当前合同合同下拉（从台账带入时默认选中）+ 合同摘要（承租方 / 档口 / 面积 / 租期 / 年租金 / 状态）
① 合同基本信息对齐线下《出租合同台账》21 字段；可改字段用橙色底，其余只读
② 本次变更摘要实时 diff（改前 → 改后）+ 自动变更类型标签 + 「共 N 处修改 → 只生成 1 条变更单」
③ 变更原因变更原因（必填，商户可见）；本环节不上传附件 —— 盖章件在审核通过后再上传（见 03-合同变更审核.md）
驳回修正模式带 ?bg={变更单号} 进入：标题显示「驳回修正 · 同单号重新送签」，红条展示驳回原因，字段预填上次修改值，提交按钮变「修正后重新送签」，单号复用不新建
底部取消 / 提交变更并送签

1.6 交互规则

元素条件结果
修改任一橙色字段—② 区实时刷新 diff 与变更类型；无修改时不显示
提交至少 1 处修改 + 原因必填生成 1 条变更单；需重签 → 「待签署」（发短信）；免重签 → 「待审核」；90 秒后跳回变更审核页并按合同号过滤
提交（无修改）—拦截：「请至少修改一处需要变更的字段（橙色底输入框）」
提交（无原因）—拦截：「变更原因必填（商户端会看到）」
提交（证件号原值为空时，v1.17）—拦截：「本合同证件号为空（身份待补全），请在「证件号」栏补齐后再提交（合同正文主体栏不能为空）」；位数不足拦截「请填写完整身份证号（18 位，末位可为 X）」
切换合同—重新加载字段，清空原因（避免串味）
取消—返回台账，不保存

1.7 业务规则

编号规则
CC-1一条变更单承载多条字段差异，不得让专员为"改租金 + 改租期"发起两次
CC-2变更类型由修改的字段自动推导，可叠加（如「租金变更 + 租期变更」）
CC-3需重签判定：租金/租期/面积/承租方/主体重大项 → 重签；仅联系人/电话 → 免重签
CC-4合同号不变，提交后为 v+1；提交仅生成待签协议，不立即改台账数值
CC-5提交后原合同状态置「变更中」，买家/商户侧展示「变更中 · 待签署」
CC-6待签署阶段专员可「催签 / 撤回」；撤回后商户端待签任务消失，变更单「已撤回」
CC-7一个合同同一时间只允许一条在途变更单（待签署/待审核）；已有在途单 → 拦截并提示先去处理
CC-8驳回后同单号重新送签：专员驳回多为「商户签名不合格」→ 从审核页「修改后重新送签」回到本页，带出上次修改值，提交后同一个变更单号回「待签署」（记录送签次数），不新建单、不用重新填一遍
CC-9发起时不传附件：盖章件在审核通过后于变更审核列表上传（变更后合同下载 → 双方盖章 → 回传扫描件）；工商变更证明等材料在审核时线下核验

1.8 异常与边界

场景处理
合同已有在途变更单拦截，提示：「该合同已有在途变更单（BG20xx），请先完成审核或撤回」
合同已终止 / 已作废不允许发起（入口不可用）
主体类型由个人→企业必须同时填企业名称 + 统一社会信用代码 + 联系人 + 电话，否则拦截
面积改小但已缴租金不退提示「面积调整不影响已缴租金，差额在下一租赁年度抵扣」
