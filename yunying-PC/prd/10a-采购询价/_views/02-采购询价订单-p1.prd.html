1. 采购询价订单 mall-order-inquiry.html

1.1 页面说明

项内容
页面目标专项管理询价产生的订单（不进外采"全部订单"列表），字段对齐普通订单 + 需求溯源
使用角色运营专员 / 主管（备注、取消）、财务（只读金额）
入口菜单 → 商城运营 → 订单管理 → 采购询价订单
前置买家在端上选标成交
后置支付 / 物流 / 售后由外采 igshop 承载
本页是三兄弟的第一张（询价 inquiry），后两张见 10b-商城运营/02-拼单集采订单.md、03-样品打样订单.md、04-定制订单.md，共用同一套"基础信息块 + 溯源块"结构。

1.2 本页端间关系

项内容
本页数据来源选标成交后生成（需求快照 + 中标报价）
本页操作的跨端影响取消订单 → 买家端订单状态变更 + 退款（外采规则）
依赖的其他端页面买家端 order-detail-inquiry.html（询价订单详情）
不涉及的端商户端发货（走外采订单能力）
一致性要求商品明细 = 需求快照，不随需求后续改动变化

1.3 页面结构

区块内容
顶部标题 + 订单类型标识
状态 Tab全部 / 待付款 / 待发货 / 已发货 / 已完成 / 已取消（对齐外采口径，去掉"无效/已删除"）
统计卡（6）订单总数 / 待付款 / 待发货 / 已完成 / 近 30 日成交金额 / 选标→支付转化率
筛选区订单号·交易单号 + 关联需求编号 + 买家会员 + 卖家店铺 + 支付状态 + 发货状态 + 时间区间
列表10 列
详情抽屉基础信息 / 需求溯源 / 报价版本记录 / 履约信息 / 操作日志
操作详情 / 备注 / 取消（仅待付款，二次确认）/ 导出（主管）

1.4 列表、筛选与排序

项目规则
默认排序下单时间倒序
分页不分页（原型单页演示）
筛选组合条件之间 且
状态 Tab与订单状态联动
空结果「暂无符合条件的订单」
与分册的偏差：分册 §8.3 列了 13 列（含"支付状态""发货状态""下单时间"分开），原型把 支付/发货 合并为一列、省去"下单时间"→ 实际 10 列。以原型为准。

1.5 字段规格

列字段说明
订单号order—
关联需求demandNo可跳 P1 需求详情
需求标题demandTitle代替商品列，带「询价」角标
买家会员buyer脱敏
卖家店铺shop—
数量/单价qty / price成交单价
订单金额amount—
支付/发货pay / ship合并双标签
订单状态status外采主状态
操作—详情

详情抽屉 5 段

段内容
① 基础信息（对齐普通订单）订单号 / 交易单号 / 下单时间 / 买家会员 / 联系人 / 收货地址 / 支付方式 / 支付状态
② 需求溯源（个性化）原始需求编号+标题 → 中标报价（单价 / 数量 / 交期承诺 / 样品支持 / 是否含运费）
③ 报价版本记录改价时间线（含"已改价 N/2"）
④ 履约信息发货状态 / 物流单号 / 售后状态（注明复用外采）
⑤ 操作日志创建 / 支付 / 发货 / 收货 / 取消时间线

1.6 交互规则

元素显示条件可点条件点击后禁止表现
详情始终始终抽屉（5 段）—
跳关联需求有需求号始终跳 P1 并定位—
备注始终专员/主管追加运营备注—
取消订单状态=待付款专员/主管二次确认弹窗 → 已取消非待付款 → 无按钮
导出始终仅主管Excel专员 → 按钮隐藏

1.7 业务规则与计算口径

编号规则触发处理影响端
R-07不进外采"全部订单"任何时候仅本页可见—
R-08商品明细 = 需求快照生成不随需求改动—
R-09取消仅限待付款取消已支付只能走售后端上
R-10选标 24h 未付自动作废定时订单取消 + 需求关闭（不回滚）两端
R-11选标→支付转化率渲染已支付 ÷ 已选标订单数—
R-12财务只读财务角色无备注/取消—

1.8 异常与边界

类型场景系统行为提示文案

数据无匹配结果空态【已实现】暂无符合条件的订单
依赖外采发货延迟物流状态只读—
