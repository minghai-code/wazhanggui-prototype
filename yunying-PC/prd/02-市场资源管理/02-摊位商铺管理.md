## 1. 摊位商铺管理 `resource-unit.html`

### 1.1 页面说明

| 项 | 内容 |
|---|---|
| 页面目标 | 资源单元总台账；合同同步匹配的结果在这里落成"当前租户 + 租期"；异常在这里人工处理 |
| 使用角色 | 物业（全操作）、运营（标记/同步/异常）、财务（只读）、合同专员（只读） |
| 入口 | 菜单 → 市场资源管理 → 摊位商铺管理；或 P1 楼层「查看档口」 |
| 前置 | 已有楼栋楼层；05 合同已导入合同 |
| 后置 | 档口状态/租户供缴费、商户识别、买家端导航；异常清单回推 05 修正 |

### 1.2 本页端间关系

| 项 | 内容 |
|---|---|
| 本页数据来源 | 物业录入（属性）+ **05 合同事件/兜底同步**（状态与租户）+ 物业登记（竞拍） |
| 本页操作的跨端影响 | 装修/停用 → 买家端隐藏该档口、商户端「我的档口」显示装修中；批量导入 → 买家端点位可选 |
| 依赖的其他端页面 | `mai-APP/market-map.html`（档口着色）、`shanghu-APP/property.html`（我的档口，待接） |
| 不涉及的端 | 买家端**不可见**承租人姓名、身份证、空置原因 |
| 一致性要求 | 编号全端唯一；状态变更 ≤5s 同步买家端；身份证脱敏不可绕过 |

### 1.5 字段规格

#### 1.5.1 统计卡（7 个）

| 卡片 | 口径 | 副文案 |
|---|---|---|
| 档口总数 | 全部资源 − 公共设施 | 不含公共设施 |
| 空闲 | 状态=空闲 | 无生效合同 |
| 在租 | 状态=在租 | 合同匹配成功 |
| 装修中 | 状态=装修中 | 物业标记 |
| 停用 | 状态=停用 | 不计出租率 |
| 出租率 | 在租 ÷ 可租，四舍五入 1 位小数 | 可租 = 总数 − 停用 − 公共设施 |
| **匹配异常** | 异常状态=待处理（**红色底卡**，数字红字） | 待人工处理 |

#### 1.5.2 台账表（11 列）

| 列 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 档口编号 | `no` | 文本 | **全端唯一**，如 `1F-A08`；已使用不可改 |
| 楼栋/楼层 | `b` / `floor` | 文本 | 显示 `A 栋 · 1F` |
| 类型 | `type` | 枚举 | 档口 / 办公室 / 店面 / 公共设施 |
| **等级** | `lv` | 枚举 | **仅档口**：精品摊（5 年一签 / 保证金 2 万）/ 普通摊（3 年 / 1 万）；缺省按「普通摊」 |
| 面积(㎡) | `area` | 数字 | 1 位小数；缴费计费基数 |
| **计租** | 派生 | 文本 | 档口/店面「按面积 ¥38/㎡·月」；办公室、公共设施 `—` |
| 状态 | `status` | 枚举 | 空闲 / 在租 / 装修中 / 停用（四色标签） |
| 当前租户 | `tenant` | 文本 | **合同承租人姓名**；空闲 `—` |
| 租期起止 | `lease` | 日期区间 | 起止同日显示单日；无合同 `—` |
| 平面图 | 派生 | 链接 | 「已标注」/「未标注」，点击跳 P3 定位 |
| 操作 | — | — | 详情 / 装修·停用（或恢复）/ 查看合同 |

#### 1.5.3 异常表（8 列）

| 列 | 字段 | 说明 |
|---|---|---|
| 异常类型 | `errType` | **编号未匹配**（红）/ **重复生效合同**（橙）/ **停用档口命中**（红） |
| 合同号 | `contract` | 05 合同编号 |
| 合同中的档口编号 | `refNo` | 合同侧填写值（多为错填），红字加粗 |
| 承租人 | `tenant` | 姓名 + 身份证脱敏 |
| 租期 | `lease` | — |
| 产生时间 | `createdAt` | 到分钟 |
| 处理状态 | `state` | **待处理 / 已处理**（实现中无"已忽略"） |
| 操作 | — | 处理 / 重新匹配 |

**异常类型 × 处置结果**（三个分支行为不同，不能写成一句）

| 类型 | 触发原因 | 点「处理」 | 点「重新匹配」 |
|---|---|---|---|
| 编号未匹配 | 合同里的编号在本模块查不到 | 直接置「已处理」 | **失败**，状态不变。提示「档口编号 {code} 在本模块不存在，请先补录档口或在合同侧修正编号」 |
| 停用档口命中 | 编号存在，但该档口状态=停用 | 直接置「已处理」 | **告警**，状态不变。提示「{code} 为『停用』档口，请核实是停用标记错误还是合同错误」 |
| 重复生效合同 | 同档口两份生效合同且租期重叠 | 直接置「已处理」 | **成功**，置「已处理」。以生效日期最新的一条作为当前租户 |

> **v1.2 已补**：点「处理」打开弹窗，必选**处理方式**（已在合同侧修正编号 / 已补录该档口 / 确认无需处理）+ 必填**处理说明**；处理后记录 `way / note / handledAt`，状态列 hover 可看说明。
