1. 签到管理 activity-checkin.html

1.1 页面说明

项内容
页面目标现场核销 + 签到记录管理（手工补签、撤销、爽约）
使用角色运营专员 / 主管
入口活动列表行内「签到」；活动详情「签到台」
前置活动处于进行中（签到窗内）
后置签到状态回写报名单，签到率与爽约进统计

1.2 本页端间关系

项内容
本页数据来源报名单（已通过）+ 现场核销
本页操作的跨端影响核销 → 商户端「我的报名」显示已签到 + 时间；撤销 → 回到未签到
依赖的其他端页面shanghu-APP/shanghu-activity-checkin.html（商户自己主办的活动）、my-activities.html（签到码）
不涉及的端买家端
一致性要求核销即时（≤2s）；重复核销幂等，返回首次时间

1.3 页面结构

区块内容
顶部面包屑（活动名）+ 标题 + 「报名名单」「导出签到表」
筛选区（6 项）活动名称（可搜索下拉，显示核销中/未开始/已关闭）/ 签到状态 / 签到方式 / 签到时间 / 关键词 / 查询·重置
核销台（2/3 宽）标题 + 当前活动名 + 演示码提示 + 输入框（6 位 / 扫码）+ 核销按钮 + 结果区
签到进度（1/3 宽）已签到 / 应到 / 签到率（范围随筛选变）
表格10 列
行操作手工核销 / 标记爽约 / 撤销核销 / 改回未签到

1.4 列表、筛选与排序

项目规则
默认排序签到时间倒序（未签到按提交时间）
分页不分页
筛选组合条件之间 且
活动下拉可搜索；每项显示人数与状态（核销中 / 未开始 / 已关闭）
进度口径选中活动 → 本场签到率；全部活动 → 全局签到率
空结果「没有符合条件的签到记录」
导出当前筛选范围导出

1.6 交互规则

元素显示条件可点条件点击后禁止表现
核销始终已选活动 + 窗口内校验 6 位 → 查码 → 判活动 → 判重复 → 置已签到五类失败见 §1.5
扫码 / 输码始终始终回车即核销—
手工核销状态=未签到运营直接置已签到 + 记录方式=手工—
标记爽约状态=未签到运营置爽约活动未结束也可标（人工判断）
撤销核销状态=已签到运营二次确认 → 回未签到原型未要求填原因（见 A-53）
改回未签到状态=爽约运营回未签到—
导出签到表始终运营/主管当前筛选导出0 条 → 拦截

1.7 业务规则与计算口径

编号规则触发处理影响端

R-34签到率活动开始后才算渲染未开始显示 —详情/看板

1.8 异常与边界

类型场景系统行为提示文案
数据未选活动就核销结果区红【已实现】「请先选择活动」/「核销必须指定一场活动」
数据窗口未开 / 已关结果区红【已实现】「签到未开始」/「签到窗已关闭」
数据输入非 6 位结果区红【已实现】「签到码格式不对」/「请输入 6 位数字码」
数据码不存在结果区红【已实现】「无效签到码」/「该码不存在，请核对后重试」
数据码属于其他活动结果区红【已实现】「活动不匹配」/「该码属于「{活动}」，请切换活动」

数据筛选无结果空态【已实现】「没有符合条件的签到记录」
数据无数据导出拦截【已实现】「当前筛选无数据，无法导出」
