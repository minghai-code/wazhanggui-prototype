1. 活动审批 activity-approve.html

1.1 页面说明

项内容
页面目标商户提交的活动在这里审核：左边队列、右边预览、底部决策
使用角色运营专员 / 主管
入口活动列表顶部「活动审批」（红点=待审数）；或列表行内「审批」带 ?id=
前置存在待审批活动
后置通过 → 上架并在商户端可见；驳回 → 通知商户改后重提（编号不变）

1.2 本页端间关系

项内容
本页数据来源商户端 shanghu-activity-apply.html 提交的申请
本页操作的跨端影响通过 → 商户端「活动参与」立即出现；驳回 → 商户端显示驳回原因且可改后重提
依赖的其他端页面shanghu-APP/shanghu-activity-manage.html（商户看状态与原因）
不涉及的端买家端
一致性要求审批结果 ≤5s 同步商户端；驳回原因必填且商户可见

1.3 页面结构

区块内容
顶部返回 + 标题「活动审批」+ 说明（商户活动需审核；平台自办免审）
左侧队列（340px）Tab（待审批 / 已通过 / 已驳回） + 卡片列表（活动名 / 商户 / 提交时间 / 名额）
右侧预览基本信息 + 详情正文 + 地点 + 报名设置 + 系统预检清单
底部操作「驳回」「通过并上架」（在预览区或弹窗）
弹窗驳回（原因枚举 + 说明必填）

1.4 列表、筛选与排序

项目规则
Tab待审批（默认）/ 已通过 / 已驳回，Tab 上带条数
排序提交时间倒序（最早提交在上，先到先审）
分页不分页（队列滚动）
空态每个 Tab 各自空态（见 A-24）

1.5 字段规格

队列卡片

字段说明
活动名称加粗
类型标签
商户提交方名称
提交时间2026-10-15 10:20
名额人数
版本ver（重提 +1，用于识别改过几次）

右侧预览

分区内容
基本信息名称 / 类型 / 商户 / 联系人电话 / 简介 / 详情正文
时间与地点报名起止 + 活动起止 + 地点
报名设置名额 / 是否审核 / 同行上限 / 报名字段
系统预检4 项，逐项 ✅/⚠️：时间合法、名额合理、地点与联系人已填、无绝对化用语

驳回弹窗

字段必填可选值
驳回原因（枚举）是内容不合规 / 信息不完整 / 时间地点冲突 / 名额设置不合理 / 其他
具体说明是自由文本，「商户需要知道怎么改」

1.6 交互规则

元素显示条件可点条件点击后禁止表现
Tab 切换始终始终切队列，右侧预览清空或保持—
队列卡片始终始终右侧加载该活动预览—
通过并上架选中待审批运营二次确认 → 状态置已通过 + 上架预检有 ⚠️ 仍允许（人工判断）
驳回选中待审批运营弹窗（枚举 + 说明）→ 确认说明为空 → 拦截
查看活动详情选中任一始终跳 P6 ?id=—

1.7 业务规则与计算口径

编号规则触发处理影响端
R-16通过即上架点通过audit=已通过 + online=上架 + 按时间定位 life商户端立即可见
R-17驳回原因 + 说明双必填点驳回任一为空 → 拦截商户端可改后重提
