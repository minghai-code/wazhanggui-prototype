1. 报名管理 activity-signup.html

1.1 页面说明

项内容
页面目标跨活动查看与处理报名：审核、驳回、取消、补录、导出
使用角色运营专员 / 主管
入口活动列表行内「报名」；活动详情「报名管理」
前置已有报名数据
后置审核结果同步商户端；名额占用/释放实时生效

1.2 本页端间关系

项内容
本页数据来源商户端自主报名 + 现场补录 + 批量导入
本页操作的跨端影响通过 → 商户端「我的报名」状态变更 + 生成签到码；驳回/取消 → 释放名额
依赖的其他端页面shanghu-APP/activity-signup.html、shanghu-APP/my-activities.html
不涉及的端买家端
一致性要求审核结果 ≤5s 同步；名额释放即时；手机号脱敏不可绕过

1.3 页面结构

区块内容
顶部返回 + 标题 + 「报名名单」跳转 + 「导出名单」
筛选区（7 项）活动名称（可搜索下拉）/ 关键词 / 审核状态 / 签到状态 / 来源 / 提交时间 / 查询·重置
摘要条活动数 · 已占位 · 待审核 · 已通过 · 已签到 · 已取消 · 已驳回 · 爽约（随筛选变）
批量操作条批量通过 / 批量驳回 / 取消选择（勾选后出现）
表格勾选 + 11 列
弹窗批量导入（粘贴 CSV）/ 现场补录 / 驳回（原因）/ 取消报名 / 导出留痕

1.4 列表、筛选与排序

项目规则
默认排序提交时间倒序
分页不分页（本期单活动报名 < 500）
筛选组合条件之间 且
活动下拉可输入关键词过滤；每项显示该活动报名条数；含「全部活动」
摘要条口径随当前筛选范围计算，不是全库
空结果「没有符合条件的报名记录 —— 换个筛选条件试试」
导出当前筛选范围内导出，脱敏 + 留痕

1.6 交互规则

元素显示条件可点条件点击后禁止表现
批量通过勾选 ≥1 且含待审核运营仅待审核行变已通过，其余忽略未勾选 → 提示 A-29
批量驳回勾选 ≥1 且含待审核运营弹窗填原因 → 驳回并释放名额同上
批量导入始终运营弹窗（下载模板 + 粘贴）—
现场补录始终运营弹窗（必选活动）缺姓名/手机 → 拦截
导出名单始终运营/主管填原因留痕 → 导出当前筛选 0 条 → 拦截
查看完整手机号有手机号运营填原因 → 显示 + 留痕—
行内通过/驳回待审核运营直接处理非待审核 → 不显示
取消报名非已取消运营确认 → 释放名额—
标记签到未签到运营直接置已签到已签到 → 换为撤销入口（在签到页）

1.7 业务规则与计算口径

编号规则触发处理影响端

R-22驳回/取消释放名额状态变更hold -= (1+同行)商户端余量
R-23补录手机号同活动唯一保存重复 → 拦截—

R-26手机号默认脱敏渲染列表全部脱敏—
R-27补录必选活动保存未选 → 拦截—

类型场景系统行为提示文案
