1. 团体研学管理 study-group.html

1.1 页面说明

项内容
页面目标团体申请审核通过后生成的批次跟进：责任书签署进度、签到进度
使用角色文商旅运营专员、运营主管
入口菜单 → 文商旅管理 → 研学 → 团体研学管理
前置P1 团体申请已审核通过（生成批次）
后置责任书全部签署后可导出；签到进度实时可见

1.2 本页端间关系

项内容
本页数据来源P1 审核通过自动生成批次；家长/学校在端上签署
本页操作的跨端影响一键催收 → 未签家长收到短信；隐藏 → 端上不可见
依赖的其他端页面买家端「我的研学」进度、责任书签署页
不涉及的端商户端
一致性要求责任书签署数 = 已签署人数；签到进度来自现场扫码

1.3 页面结构

区块内容
顶部标题「团体研学管理」+ 一键催收未签 + 导出批次
统计卡（4）进行中批次 / 待签署责任书 / 本月已签到 / 本月接待人次
筛选区关键词 / 学校 / 路线 / 日期 / 状态 + 查询 + 重置
Tab 条（3）批次列表 / 责任书签署 / 签到记录
列表10 列 + 分页
抽屉批次详情（名单 / 责任书签署记录 / 签到记录 / 评价）

1.4 列表、筛选与排序

项目规则

1.7 业务规则与计算口径

编号规则触发处理影响端
R-08批次由 P1 通过自动生成审核通过一条申请一个批次—
R-09签署进度 = 已签 / 应签签署实时更新端上
R-10全员已签才可导出行程单导出部分未签 → 提示并对未签标红—
R-11未签提醒 3 天 / 1 天定时短信 + 站内端上
R-12签到进度来自现场扫码扫码实时端上
