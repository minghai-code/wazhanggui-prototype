1. 技术成果管理 chain-tech-achv.html

1.1 页面说明

项内容
页面目标维护高校/研究所的新技术新成果（入库 → 发布 → 被对接跟进），并维护技术专家库
使用角色产业服务专员、产业服务主管
入口菜单 → 产业链服务 → 技术共享 → 技术成果管理
前置成果资料由业务方线下收集
后置端上 tech-service.html 成果 Tab / 技术专家区块可见
v1.2 订正：审核发布环节本期不做，原型为 草稿 → 已发布 → 已下线。与 P2 共用同一张「对接记录」模型（双向撮合）。

1.2 本页端间关系

项内容
本页数据来源专员录入（首批建议 8–12 条真实成果）
本页操作的跨端影响发布 → 买家端成果 Tab 可见；专家发布 → 端上「技术专家」区块
依赖的其他端页面mai-APP/tech-service.html（成果 Tab + 专家区块）
不涉及的端商户端（本页成果只投买家端）
一致性要求成果被对接次数 = 对接记录数；专家参与对接数同源

1.3 页面结构

区块内容
顶部标题「技术成果管理」+ 导出 + 新增成果
统计卡已发布成果 / 草稿（未发布）/ 对接中 / 被对接次数 Top / 平均匹配时长·成功率
筛选区关键词 + 所属领域 + 提供方类型 + 成熟度 + 状态 + 查询 + 重置
Tab 成果成果表（9 列）
Tab 专家专家表（8 列）
抽屉成果（名称/提供方/领域/简介/技术指标/成熟度/应用场景/合作方式/联系方式/附件/投放端）

1.4 列表、筛选与排序

项目规则
默认排序已发布优先，其次对接次数降序
分页不分页
筛选组合条件之间 且
提供方类型高校 / 研究所 / 企业 / 其他
成熟度实验室 / 中试 / 量产
空结果「暂无成果，可由业务方线下收集后录入」

1.5 字段规格

成果表（9 列）：成果 · 提供方 · 所属领域 · 成熟度 · 应用场景 · 合作方式 · 对接次数/结果 · 状态 · 操作

专家表（8 列）：专家 · 所属单位 · 职称/头衔 · 研究方向 · 可服务领域 · 参与对接 · 状态 · 操作

关键字段说明
coopType合作方式（技术转让 / 合作开发 / 委托研发 / 技术服务），至少选一种
maturity实验室 / 中试 / 量产
files说明书 / 专利（附件）
matchCount对接次数（同源对接记录）

1.6 交互规则

元素显示条件可点条件点击后禁止表现

1.7 业务规则与计算口径

编号规则触发处理影响端
R-13成果与需求共用对接模型发起同一张 Match 表，双向可发起—
R-14被对接次数 = 对接记录数每次对接列表 Top 排名依据驾驶舱
R-15合作方式至少一种发布空 → 拦截端上
R-16专家不新增菜单—成果页内 Tab—
R-17附件不压缩上传说明书/专利原样保存—

1.8 异常与边界
